# Story 3d.8: Soft Hide/Archive Obsolete Executions

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

> **⚠️ READ FIRST — most of the plumbing for this story already exists; the net-new surface is small and the biggest trap is *over*-building.** This is a governed-triage feature (hide an obsolete run from the queue, reversibly, without erasing audit history). Build on what is already there; do not re-create it:
>
> - **`archived_at` ALREADY EXISTS on `workflow_runs`.** It was shipped in `V1__create_workflow_core_tables.sql` (line 19, `archived_at timestamptz null`) under the retention-readiness rule, and is **already** mapped end-to-end: `WorkflowRunEntity.archivedAt` (`@Column(name = "archived_at") OffsetDateTime`, with getter/setter), `WorkflowRunSnapshot.archivedAt` (record component), and `WorkflowRunEntityMapper.toSnapshot` already copies it. **There is NO new column to add.** The epic AC wording ("additive migration adds the marker") is stale — the marker is already on disk. The ONLY candidate migration is an *optional* partial index for the include-archived/sweep query path (see R1 + Open Decision #1).
> - **The "cascade" is a VIEW/SCOPE concern, NOT a child-row write** (ADR 0027 D1 + Consequences→Neutral: *"The cascade over artifacts/runner_executions/links is a view/scope concern, not a row-deletion cascade."*). The run's `archived_at` is the **single source of truth**. Artifacts / runner_executions / integration_links are only ever read **in the context of a run** (by `workflow_run_id`, in the run-detail view) — there is **no global operator list of artifacts/executions/links**. So hiding the run from the queue list scopes its entire subtree out of default operator flows for free. **DO NOT stamp `archived_at` onto the child rows** — that conflates run-hide with lineage-archival (artifacts/links already use their *own* `archived_at` for supersede/lineage semantics) and would make un-hide resurrect rows that were independently archived. One write: the run's `archived_at`.
> - **`WorkflowController.listWorkflows`** (`GET /api/v1/workflows`, line ~106) is the queue endpoint. It supports `?state=` + `?limit=` today via `WorkflowRunReadPort.listRuns(stateFilter, limit)` → `WorkflowRunPersistenceAdapter` → `WorkflowRunRepository.findAllByOrderByCreatedAtDescIdDesc` / `findByCurrentStateOrderByCreatedAtDescIdDesc`. **You add an `includeArchived` flag that defaults to filtering `archived_at IS NULL`.** The single-run fetch (`GET /api/v1/workflows/{id}`) has **NO** archive filter and MUST keep returning archived runs (that is the audit-queryable path — AC6).
> - **Governed event append** is `WorkflowEventWritePort.append(WorkflowEventRecord)` (see `RecoveryService` ~L581 for the canonical call). The record carries `eventType`, `priorState`, `resultingState`, `actorIdentity`, `actorType`, `reason`, `interventionMarker`, `details` map. For archive/un-archive **`priorState == resultingState`** (archiving does NOT change `current_state`) and **`interventionMarker = true`** (human triage action).
> - **Idempotent mutation pattern**: copy a simple run-action endpoint — `retry-workflow` / `takeover-workflow` in `WorkflowController` (~L795). Headers: `Idempotency-Key` + `X-Actor-Identity` (resolved via `localActorIdentityResolver.requireSafe/resolve`), `@Valid @RequestBody` with a `reason`. The generic `IdempotencyService.checkAndReserve(key, commandType, actorIdentity, fingerprint)` → `complete(...)` is the idempotency engine (3c-8 used it directly without touching `WorkflowCommandFingerprintFactory`).
> - **CLI parity**: `WorkflowCommands` (`adapters/cli`) — copy the `retry` command (~L546): `@Argument runId`, `--actor-identity`, `--actor-type`, `--idempotency-key`, `--correlation-id`, `--reason`, `--verbose`; `emitSuccess`/`emitFailure`/`codeFor(de)` error handling.
>
> **THE FOUR THINGS THAT ARE GENUINELY NET-NEW:**
> 1. **Two new `WorkflowEventType`s** — `workflow.archived` / `workflow.unarchived` — which trip the **"new WorkflowEventType → two fixture sites"** rule (enum + `workflow-event-types.fixture.json`) **and** the byte-identical OpenAPI enum regen ([[new-workfloweventtype-fixture-sites]]).
> 2. **Two new `AllowedAction`s** — `archive_run` / `unarchive_run` — enum + `allowed-actions.placeholder.json` fixture (NO DB CHECK — allowed-actions are enum↔JSON only), threaded into `computeActionMatrix` in `WorkflowInspectionService` (the ArchUnit-pinned single source).
> 3. **One new three-sites `DomainErrorCode`** — `ARCHIVE_NOT_APPLICABLE` (mirrors the existing `RETRY_NOT_APPLICABLE`) — because **`ACTION_NOT_ALLOWED` does NOT exist** and there is NO generic allowed-action guard; the precondition (archive only a not-archived run; un-archive only an archived run) is enforced in the service ([[new-domainerrorcode-three-sites]]).
> 4. **A run-archive write seam** — a `markArchived(publicId, instant)` / `clearArchived(publicId)` capability (mirror `IntegrationLinkPersistenceAdapter.markArchived` ~L336) on the workflow-run write port — the entity setter exists, but nothing currently *clears or sets* `workflow_runs.archived_at`.

## Story

As an operator,
I want to hide (archive) a run whose source ticket has been removed — and un-hide it later — through a governed, reversible, audited action that never erases history,
so that my Run/Review Queue stays focused on live work while the full record of every run remains inspectable.

## Acceptance Criteria

> These ACs are **reconciled** against the live schema (the `archived_at` marker + its entity/snapshot/mapper wiring already exist), the queue read path, the event-append + idempotency + allowed-action conventions, the absence of an `ACTION_NOT_ALLOWED` code, and ADR 0027's "view/scope, not row-deletion cascade" stance. Where epic wording assumes infrastructure that does not exist (or already exists), the reconciled wording below is authoritative; rationale is in Dev Notes → "Why these ACs are reconciled."

1. **Archive marker (no new column).** Hiding a run sets `workflow_runs.archived_at = now()` (the column already exists, V1) and **never** deletes any row and **never** touches `workflow_events`; append-only history (FR47) is fully preserved. No `workflow_runs` schema change is required for the marker. **Optionally** a replay-safe partial index `idx_workflow_runs_archived_at … where archived_at is not null` is added at the next-free Flyway version (see R1/Open Decision #1; **V19 is already claimed by story 3d-1 and 3d-3 also migrates — use the next free number at implementation time, do NOT hardcode V19**).

2. **Cascade is a scope concern, not a child write.** Hiding a run scopes its related artifacts / runner_executions / integration_links out of default operator views by virtue of the run itself leaving the default queue — those rows are only ever read in the context of their run (by `workflow_run_id`), and there is no global operator list of them. The child rows are **left durably intact and their own `archived_at` is NOT mutated** (run-hide ≠ lineage-archival). Audit/inspection of the run-detail subtree still works for an archived run (AC6).

3. **Operator-initiated hide (REST + CLI, allowed-action-gated, audited).** A `POST /api/v1/workflows/{workflowRunId}/archive` endpoint (+ a CLI `archive` command, story 1.7 parity) sets the marker and appends a governed `workflow.archived` event (operator identity, timestamp, `reason`/why) in **one transaction**. The action requires `Idempotency-Key` + actor identity (story 1.9 / 2.13 conventions); a same-key replay is a no-op replay. The `archive_run` action is surfaced via the backend-derived allowed-action matrix (story 2.14).

4. **Reversible un-hide (REST + CLI, allowed-action-gated, audited).** A `POST /api/v1/workflows/{workflowRunId}/unarchive` endpoint (+ CLI `unarchive`) clears `archived_at` and appends a governed `workflow.unarchived` event — same idempotency + actor + allowed-action conventions. Hide is **not** a one-way destructive action (ADR 0027 D5). The `unarchive_run` action is surfaced only for an already-archived run.

5. **Queue archived state + "include archived" filter.** `GET /api/v1/workflows` defaults to **hiding** archived runs (`archived_at IS NULL`) and accepts `?includeArchived=true` to include them; `WorkflowSummaryResponse` gains an `archivedAt` field so the queue can render an archived/hidden badge. The Run/Review Queue UI shows the archived state with a color-independent signifier and offers an "include archived" toggle. Epic 4's operator queue (story 4.2) honors the same state (de-dup note — do not build a second filter).

6. **Archived runs remain audit-queryable.** `GET /api/v1/workflows/{workflowRunId}` (single fetch) returns an archived run unchanged (no archive filter on the by-id read), and the `?includeArchived=true` list path reaches it — so a hidden run is never lost. Direct inspection of its artifacts/executions/events still resolves.

7. **Optional auto-on-ticket-removal flagging.** *Optionally* (behind a default-OFF feature flag), a scheduled scan detects source-ticket removal via the ticket-source adapter (an active `integration_links` row whose `TicketSourceAdapter.fetchTicketByReference` now returns empty / 404) and auto-archives the related run — recorded as a `workflow.archived` event with a SYSTEM/MACHINE actor + a `reason` distinguishing it from a manual hide. The manual hide/un-hide path (AC3/AC4) is the **required** core; the auto path is optional and per-item-isolated (one ticket's failure never aborts the batch). See R5/Open Decision #4.

8. **Epic 5 boundary recorded.** True purge / physical deletion / retention windows for archived runs are explicitly **out of scope** here and remain owned by Epic 5 (the `repoRemovedFromSource` job); a code comment + the 3d-10 doc record the split.

9. **Problem Details + OpenAPI + drift.** The hide/un-hide endpoints + DTOs appear in the regenerated `openapi.json` snapshot with typed errors: `RUN_NOT_FOUND(404)`, the idempotency codes (`MISSING_IDEMPOTENCY_KEY`/`INVALID_IDEMPOTENCY_KEY`/`IDEMPOTENCY_KEY_CONFLICT`), and the new **`ARCHIVE_NOT_APPLICABLE`** (archive an already-archived run, or un-archive a not-archived run) — registered three-sites. The two new event types + two new allowed-actions pass their drift tests; `FlywaySchemaContractTest` stays green (and gains the partial-index assertion only if Open Decision #1 ships the index).

10. **Tests.** Coverage asserts: hide sets `archived_at` + appends `workflow.archived` + leaves `workflow_events` untouched (no mutation/delete; FR47); the archived run leaves the default queue but is reachable via by-id fetch + `?includeArchived=true`; un-hide clears the marker + appends `workflow.unarchived`; the `includeArchived` filter; `ARCHIVE_NOT_APPLICABLE` on double-archive / un-archive-not-archived; idempotent replay; **no row deletion occurs anywhere**; the optional auto-archive scan flags a removed-ticket run (per-item isolation) when its flag is enabled and is inert when disabled; CLI/REST equivalence; registry/fixture/OpenAPI drift; FE Vitest + axe (queue badge + filter toggle) + a Playwright path. New `application.workflow` + `adapters.rest`/`adapters.cli` code meets the standing **≥80% line-coverage** floor.

### R1 — The marker already exists; the only schema decision is an optional index (read twice)
`archived_at` is on `workflow_runs` since V1 and fully wired (entity column + getter/setter, `WorkflowRunSnapshot` component, `WorkflowRunEntityMapper.toSnapshot` copies it). **Do not add a column. Do not write a migration to add the marker.** The single open schema question is whether to add a partial index `create index idx_workflow_runs_archived_at on workflow_runs (archived_at) where archived_at is not null;` — the V1 precedent exists for `workflow_events`/`artifacts`/`recovery_actions`. It helps the `?includeArchived=true` and (future Epic 5) sweep paths; it is cheap + replay-safe. **If you ship it, use the next-free Flyway version at implementation time — story 3d-1 already claims V19 and story 3d-3 also adds a migration**, so do NOT hardcode V19 (same stale-version drift the epic doc has elsewhere: V5→V15, V14→V17). If you ship it, add the matching assertion to `FlywaySchemaContractTest`. Default: **ship the index** (Open Decision #1).

### R2 — "Cascade" = scope, not child writes (the central ADR 0027 stance)
ADR 0027 D1 + Consequences→Neutral are explicit: the cascade over artifacts/runner_executions/integration_links is a **view/scope concern, not a row-deletion cascade**. The run's `archived_at` is the single source of truth. Because those child rows are only ever read in the context of a run (by `workflow_run_id`, in the run-detail aggregation) and there is **no global operator list** of them, hiding the run from the queue list scopes the whole subtree out of default operator flows with **zero** child-table writes. Stamping child `archived_at` would (a) be redundant, (b) collide with the children's own lineage/supersede `archived_at` semantics, and (c) make reversible un-hide ambiguous (which children do you un-archive — only the ones the run-hide touched?). **One write: the run.** Keep it that way.

### R3 — Error code + allowed-actions: no generic guard exists
There is no `ACTION_NOT_ALLOWED` and no shared "is this action allowed" service guard. The matrix in `WorkflowInspectionService.computeActionMatrix` is a **read/advertisement** surface for the UI; command services enforce their own preconditions and throw a specific code. So: the archive service enforces "not already archived" (and un-archive enforces "is archived") and throws the new **`ARCHIVE_NOT_APPLICABLE`** (precedent `RETRY_NOT_APPLICABLE` — CONFLICT, non-retryable). The allowed-action additions (`archive_run`/`unarchive_run`) are purely the UI affordance gate (story 2.14): enum + `allowed-actions.placeholder.json` (RegistryContractTest enum↔JSON; **no DB CHECK** — unlike `WorkflowState`/`WorkflowEventType` there is no `ck_*` constraint for allowed-actions), threaded into the matrix via a new `boolean archived` argument so the two actions are mutually exclusive per run.

### R4 — Event semantics: orthogonal to state
Archiving does **not** transition `current_state`. The `WorkflowEventRecord` must carry `priorState == resultingState == snapshot.currentState()` and `interventionMarker = true` (a human/governed triage action, like recovery/approval). Use `WorkflowEventDetailKeys` for `idempotencyKey`/`correlationId`/`reason` in the `details` map (see `RecoveryService` ~L581 for the exact idiom). The two new types land in the enum **and** `workflow-event-types.fixture.json`; the OpenAPI enum is regenerated byte-identically (it is NOT auto-derived — [[new-workfloweventtype-fixture-sites]]).

### R5 — Auto-on-ticket-removal is optional, default-off, per-item-isolated
The epic says "**optionally** … can flag/auto-archive". Keep it strictly opt-in behind a default-`false` flag. Hook shape: a `@Scheduled` `@Component` (model `LinearPollingHost`) that walks active `integration_links` and calls `fetchTicketByReference`; an `Optional.empty()` (source 404) on a previously-linked ticket auto-archives the run via the SAME `WorkflowArchiveService.archiveRun` (SYSTEM/MACHINE actor + a `reason` like `ticket_removed_from_source`, so the audit trail distinguishes auto from manual). Per-item isolation via a `perItemTransactionTemplate` (model `ArtifactReconciliationService`) — one ticket's failure must not abort the batch, and the watermark/loop continues. If the team would rather not ship the scheduler in 3d-8, the manual path alone satisfies AC3/AC4; ship the flag + defer the scan (note it). Epic 5 still owns *true purge* — auto-archive here only sets the soft marker.

### Open Decisions surfaced for review (do not block implementation; defaults chosen)

1. **Partial index** — default: **ship** `idx_workflow_runs_archived_at … where archived_at is not null` at the next-free Flyway version (NOT V19) + a `FlywaySchemaContractTest` assertion. Alternative: skip it (no migration at all in 3d-8) and rely on a seq-scan over the small local dataset. Proceeding with the index (cheap, replay-safe, matches the V1 precedent + future Epic 5 sweep).
2. **Error code** — default: one new three-sites `ARCHIVE_NOT_APPLICABLE` (mirrors `RETRY_NOT_APPLICABLE`) covering archive-already-archived + un-archive-not-archived. Alternative: reuse `INVALID_COMMAND_PAYLOAD` (no new code) — rejected as less precise; the epic explicitly wants a typed applicability error (it names `ACTION_NOT_ALLOWED`, which does not exist). Proceeding with `ARCHIVE_NOT_APPLICABLE`.
3. **Service home** — default: a dedicated `WorkflowArchiveService`. Alternative: extend `WorkflowCommandService` (check whether it is ArchUnit scope-protected like `RecoveryService` first — if so, a new service is mandatory). Proceeding with the dedicated service.
4. **Auto-on-ticket-removal** — default: ship the manual hide/un-hide as the required core **and** the optional scan behind a default-OFF flag (per-item isolation). Alternative: ship only the manual path in 3d-8 and defer the scheduler to a follow-up. Proceeding with both (flag default-off); confirm whether the scheduler should land here or be deferred.
5. **Event-type namespace** — default: `workflow.archived` / `workflow.unarchived` (aligns with `workflow.stateChanged`). Alternative: `run.archived` / `run.unarchived`. Proceeding with the `workflow.` namespace for consistency.
6. **Archive response shape** — default: a small `ArchiveRunResponse { workflowRunId, currentState, archivedAt }` so the client reflects the new state immediately. Alternative: reuse `WorkflowStateChangeResponse` (no `archivedAt`). Proceeding with the dedicated response.
