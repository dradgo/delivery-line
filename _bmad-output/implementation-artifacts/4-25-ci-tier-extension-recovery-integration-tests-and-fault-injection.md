# Story 4.25: CI Tier Extension — Recovery Integration Tests + Fault Injection

Status: done

## Story

As a backend developer + CI maintainer,
I want a dedicated CI tier that runs recovery integration tests with deliberate fault injection (timeout, crash, contract violation, integration conflict, artifact drift) — extending the story 1.21 + 3.34 tier order with recovery-specific gates,
so that recovery-path regressions surface in CI before reaching the foundation gate; the architecture's "recovery is part of the primary value proposition" claim is mechanically enforced.

## Context & Central Reconciliation (READ FIRST)

**This is a CI-tier + integration-test story — it adds ZERO production code.** No new `@Service`, no migration, no `DomainErrorCode`, no `WorkflowEventType`, no REST endpoint, no port method. Its entire blast radius is: (1) a new `recovery-integration` job + a `recovery-integration-gate` aggregator in `.github/workflows/ci.yml`; (2) new `*IT` scenario classes that compose EXISTING recovery services + EXISTING mock-adapter injection primitives into end-to-end fault-injection scenarios; (3) a Maven `@Tag` + `recovery-integration` profile so the tier runs a focused, named subset; (4) foundation-gate widening realized as a branch-protection required check + a light Java smoke contract; (5) a "reproduce locally" section in `docs/setup-local.md`. If you find yourself editing anything under `src/main/java` beyond a possible `@Tag` on a test-support helper, STOP — you are out of scope.

**⚠️ THE ONE FACT THAT RESHAPES THE FAULT-INJECTION HALF — every injection primitive already exists; NOTHING new is built for injection.** There is no chaos/Toxiproxy/fault-inject library in this repo, and the epic AC text implies you build one. You do NOT. The primitives are:
- **Integration-conflict injection:** `GitHubMockScenarioRegistry.seedPullRequest(...)` / `.removePullRequest(prRef)` / `.register(GitHubMockScenario)` (github-mock is the DEFAULT test profile). A test seeds an `integration_links` row (`github_pr`, `external_metadata` jsonb baseline like `{"prState":"open"}`) then forces each category by mutating the mock's PR state, then calls `IntegrationConflictDetectionService.sweep()` directly.
- **Artifact-drift injection:** seed `artifacts` / `artifact_operations` rows with **backdated `created_at`** (orphan = stale `pending` op; the age threshold is `deliveryline.artifact.reconciliation.stale-pending-minutes`), and manipulate real payload files under `LocalArtifactStore` (delete a file → missing-payload; overwrite a file OR store a wrong `checksum_value` → checksum-mismatch), then call `ArtifactDriftDetectionService.detectDrift()` directly.
- **Recovery paths:** drive the run through the real REST endpoints on `WorkflowController` (`/pause`, `/resume`, `/reconcile`, `/rerun-from-step`, `/classify-failure`) or the `RecoveryService` methods directly.

The precedent ITs that already do exactly this seeding are your templates — **read them first**: `IntegrationConflictDetectionIT`, `ConflictAutoPauseIT`, `ArtifactDriftDetectionIT`, `ArtifactDriftRepairIT` (paths in Reconciliation 3). Story 4.25 is the *composition + CI wiring* of these into named recovery scenarios; the injection mechanics are already proven.

[Source: .github/workflows/ci.yml `detect-changes` job (watched array, github-script listFiles, fail-safe branches)]

## Dev Notes

### Relevant architecture patterns and constraints

- **Zero production blast radius.** Read Reconciliation preamble + Scope Boundary twice. If a change lands under `src/main/java` (beyond an optional `@Tag`/test-support helper), it is out of scope — the recovery/reconciliation/conflict services and endpoints are all DONE (stories 4.5–4.19); 4.25 only DRIVES them.
- **Injection primitives already exist (Reconciliation 3).** GitHub mock: `GitHubMockScenarioRegistry.seedPullRequest/removePullRequest/register`, `clearTestScenarios()` in `@AfterEach`; `PullRequest(prRef, repoRef, number, sourceBranch, state, merged, url, createdAt)`. Linear mock: fixture-JSON only (no seed). Payload files: `LocalArtifactStore` writes `<deliveryline.home>/artifacts/<run>/<artifact>/v<n>/<ref>` (the `storage_ref` is that relative path) — delete/overwrite the resolved file to inject missing-payload/checksum drift. Drift/orphan: seed rows with backdated `created_at`.
- **Detection is synchronous in tests (Reconciliation 1).** `IntegrationConflictDetectionService.sweep()` and `ArtifactDriftDetectionService.detectDrift()` are called DIRECTLY; the `@Scheduled` `@ConditionalOnProperty` wrappers stay `enabled: false`. This is why there is no timing flake and why AC3's "within one detection cycle" = one `detectDrift()` call.
- **Auto-pause is opt-out in the shared profile.** `deliveryline.integration.conflict-detection.auto-pause-on-categories: []` (opted out). Scenarios that assert auto-pause must `@TestPropertySource` it back to `external_state_advanced,external_state_reverted`. Only those two categories auto-pause by default (NFR21); the other three detect-only.
- **CI conventions to match exactly (Reconciliations 5–8, 10).** No `on.paths` (use `detect-changes` + `if:`). Path-gated jobs never go in `foundation-gate.needs` (skip→fail). Merge-blocking = an always-runs aggregator registered as its own required check (mirror `runner-contract-real-gate`). `-Dfailsafe.failIfNoSpecifiedTests=false` needs the "assert ≥1 test ran" fail-open guard. Tier isolation via a `@Tag` + a profile that clears the default-exclude (mirror `docker-runner-it`). `-Djacoco.check.skip=true` (partial suite). No blanket retries — narrow, inline-justified pull/setup retries only.
- **State vocabulary (assertions).** `WorkflowState` wire values: `Paused`, `Executing`, `Investigating`, `WaitingForReview`, `Failed`, `Reconciled`, etc. `PAUSABLE_SOURCE_STATES` and `RERUN_SOURCE_STATES` (`FAILED`, `WAITING_FOR_REVIEW`) bound what a scenario can set up. Resume's "prior executing state" = the typed `priorState()` off the `Paused` event.
- **Idempotency namespacing.** The user key flows to (a) the workflow transition, (b) the runner dispatch as `key + ":runner"`, (c) the bare `recovery_actions` row. Replay is a match only on SAME run + SAME `action_type` + `result_status='succeeded'`; else `IDEMPOTENCY_KEY_CONFLICT` ([[transition-idempotencykey-is-not-a-dedupe-key]]).
- **Windows caution.** These are Docker/Testcontainers ITs → they run on `ubuntu-latest` only in CI and require a Docker daemon locally (WSL2 on Windows). Do not add them to the Windows matrix legs. The `*IT` name keeps them in Failsafe, not Surefire ([[springboot-testcontainers-test-must-be-IT]]); a `*Test` name would leak into Windows Surefire and red CI.
- **OpenAPI / FE.** This story adds no endpoints and no schema changes → NO `openapi.json` regen, NO `npm run generate-api`. If a scenario IT happens to touch a controller signature, that is a mistake (out of scope).

### Logging Requirements (project-wide standard)

The project-wide standard (add production logs on every touched service) is **not triggered by this story** because it adds no production service surface. The standard is satisfied by: (a) NOT regressing existing recovery logs (the driven services already log), and (b) optionally PINNING representative existing recovery log lines from a scenario IT via `OutputCaptureExtension`/list-appender to guard observability. Do not introduce `System.out`/`printStackTrace` in tests; use the test framework's logging. Never print corrupted payload bytes, secrets, or PII in test output.
