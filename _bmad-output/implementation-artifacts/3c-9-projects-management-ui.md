## Story

As an operator,
I want a Projects management screen — a list, a create/edit form, write-only credential controls, a connectivity-test control, and a project selector — that drives the governed `/api/v1/projects` REST contract,
so that I can configure, credential, test, and select projects without editing config files, with every control gated on backend-reported allowed actions and every surface keyboard-operable and WCAG 2.1 AA clean.

## Acceptance Criteria

> These ACs are **reconciled** against the live frontend architecture (TanStack Router file-based routes, TanStack Query + `openapi-fetch` typed client, the shadcn/ui + tokens design system, the `useWorkflowMutation` idempotency factory, the custom ESLint governance rules) and the **actually-merged backend** (eight project endpoints; **no project field on the run-read DTOs; no `projectId` queue filter**). Where the epic wording assumes a backend capability that does not exist, the reconciled wording below is authoritative; the rationale is in Dev Notes → "Why these ACs are reconciled."

1. **Navigation landmark + route.** A "Projects" link is added to the existing nav rail (`AppShell.tsx` → `NavRailContent`) and a new file-based route `src/routes/projects/index.tsx` (`createFileRoute('/projects/')`) opens a settings/configuration area **distinct** from the queue (`/workflows`) and run (`/workflows/$id`) views. The link uses the established active-link styling and is reachable in both the desktop nav and the mobile `Sheet` drawer (both render `NavRailContent`). `routeTree.gen.ts` is regenerated by the Vite plugin / `npm run routes:generate` (it is gitignored — do not hand-edit or commit it).

2. **Project list.** The Projects screen lists every project from `listProjects`, showing per project: **name**, **status** (`active`/`disabled` — rendered with a non-color signifier, icon + text), **ticket-source kind**, **repository-host kind**, **repository URL** (graceful empty state when null), and **per-role credential presence** (`configured`/`not_configured` from `Project.credentials[]`). The last connection-test **result + timestamp** is shown **per the reconciliation in R4** (client-session-scoped: the backend does not persist test history, so the list shows a stored result only after the operator runs a test this session; otherwise "Not tested"). Loading → typed `LoadingState` (variant `fetchingData`); empty → `EmptyState`; error → `ErrorState` with a `Retry` next action (mirror `QueueShell`).

3. **Create / edit form.** A create form and an edit form capture: **display name** (`@NotBlank`, ≤256), **slug** (create-only, `@NotBlank`, ≤256 — slug is **not** in `UpdateProjectRequest`, so it is read-only on edit), **repository URL** (nullable, ≤2048), **ticket-source kind** picker, **repository-host kind** picker, and **OpenSpec** toggle, with **field-level validation + explicit error identification** (mirror `SubmitRunForm`: plain `useState`, a pure `projectFormView.ts` validator, lazy `showErrors`, `<Label htmlFor>` + `aria-invalid` + `aria-describedby` + a `role="alert"` `FieldError`). Create calls `createProject`; edit calls `updateProject`. Connector-kind picker options are a frontend constant mirroring the backend `ConnectorKind` registry (`linear`, `github`, `gitlab`) — see Open Decision #3.

4. **Write-only credential controls.** Each connector role (`ticket_source`, `repo_host`) renders its presence as a **"Configured" / "Not configured"** badge (from `Project.credentials[]`, non-color signifier) with a **set/replace** affordance. Setting a credential calls `setProjectCredential` with the plaintext in `SetCredentialRequest.secret`. **The stored value is never displayed, never pre-filled, never placed in the DOM, and never exposed to assistive tech**: the input is `type="password"`, has no `value`/`defaultValue` seeded from any response, is cleared on success, and no response field ever carries a secret (`SetCredentialResponse` is `{role,status,credentialId}` only). The set/replace control fires the mutation with a **required** `Idempotency-Key` (the backend marks the header required).

5. **Connection-test control.** A "Test connection" control calls `testProjectConnection` and renders the **three** per-check results from `TestConnection.checks[]` — `repository_reachable`, `ticket_source_auth`, `repository_host_auth` — each as `pass` / `fail` / `skipped` with its secret-free `detail`. **Progress and results are announced via an `aria-live` region** (`useLiveAnnouncement` + an `announcements.ts` vocabulary entry) and **pass/fail is conveyed by icon + text, never color alone** (use `STATE_SIGNIFIERS`). A check failure is **in-band data** (HTTP 200), not an error surface; only `PROJECT_NOT_FOUND`/`UNSUPPORTED_CONNECTOR_KIND` (Problem Details) render as an `ErrorState`.

6. **Project selector (reconciled — selector + collapse only; queue-scoping deferred).** A project selector is built that **collapses to a static label when only the `default` project exists** (the live single-project state today). When ≥2 projects exist it presents a selection control. **Because the backend run-read surface carries no project field and `GET /api/v1/workflows` has no `projectId` filter (R3), the queue-filter wire-through and the per-run project-attribution badge are OUT of 3c-9 scope** and are recorded as a documented follow-up; the selector is delivered as the consumable seam (it reads `listProjects`, renders the collapse/expand behavior, and is unit-tested), not wired to mutate the queue query. See Open Decision #2.

7. **Backend-reported allowed actions (status-derived, NO role gating).** Create/edit/disable/enable/set-credential/test controls reflect **`Project.allowedActions: string[]`** (backend-derived from project status), not frontend inference. The UI **gracefully ignores unknown action values** (forward-compat per the schema note). Because projects have **no role dimension** (single-operator, no RBAC), gating is on the action-name array only — **do not introduce any role-based gating** (the `no-role-based-action-gating` ESLint rule forbids it). The `default` project never advertises `disable`; a `disabled` project advertises `enable` not `disable`.

8. **WCAG 2.1 AA.** All forms are keyboard operable with explicit labels + error identification; focus order is logical; the connection-test live region announces. An axe scan (`expectNoA11yViolations`, `wcag2aa` tags) reports **zero violations** on every documented state (list loading/empty/populated/error, create form, edit form, credential dialog, connection-test pass/fail/skipped, selector collapsed/expanded).

9. **Design-system reuse.** The UI reuses the existing shadcn/ui primitives (`Button`, `Input`, `Label`, `Select`, `Dialog`, `Card`, `Table`, `Badge`, `Alert`) + layout primitives (`Stack`, `Inline`, `Grid`, `Container`) + tokens (`state-signifiers.ts`, gap scale). **No new component primitives** are introduced under `src/components/ui/`. Feedback follows the rules: workflow/operation truth is inline (`InlineFeedback`/state components), toasts are **ancillary `.info()` only** (`no-workflow-toast-success`), every `LoadingState` is typed (`no-untyped-loading-state`), at most one primary action per surface (`single-primary-action`).

10. **Tests.** Vitest + Testing Library cover: the list (loading/empty/populated/error), the create form (validation + success + error mapping), the edit form (slug read-only, prefilled non-secret fields), credential write-only behavior (secret never in DOM/response, password input, cleared on success, idempotency-key sent), connection-test states (pass/fail/skipped + live-region announcement), and the selector (collapsed-to-label vs expanded). API is mocked via MSW (`server.use(http.…)`). An axe scan runs on each documented render state. A Playwright e2e spec (`e2e/projects-management.spec.ts`) covers the create→credential→test journey against the `mockApi` backend, plus a keyboard-only pass. New `src/features/projects/**` code meets a coverage threshold added to `vitest.config.ts` (see Task 9).

## Dev Notes

### Backend contract (exact wire shapes — from the committed `openapi.json`, post-3c-8)

The generated `schema.d.ts` (after Task 1) is the source of truth; these are the shapes to consume:

- **`Project`** (list item + create/update/disable/enable response): `id` (`prj_…`), `name`, `slug`, `status` (`'active'|'disabled'`), `repositoryUrl` (`string|null`), `ticketSourceKind` (e.g. `'linear'`), `repoHostKind` (e.g. `'github'`), `openspecEnabled` (bool), `createdAt` (date-time), `credentials: CredentialPresence[]`, `allowedActions: string[]`.
- **`CredentialPresence`**: `{ role: string, status: 'configured'|'not_configured' }` — role is the underscored wire form (`ticket_source` / `repo_host`).
- **`CreateProjectRequest`**: required `name`, `slug`, `ticketSourceKind`, `repoHostKind`; optional `repositoryUrl` (nullable), `openspecEnabled`. (`name`≤256, `slug`≤256, `repositoryUrl`≤2048; kinds `minLength:1`.)
- **`UpdateProjectRequest`**: required `name`, `ticketSourceKind`, `repoHostKind`; optional `repositoryUrl`, `openspecEnabled`. **No `slug`** (slug is immutable post-create → read-only in the edit form).
- **`SetCredentialRequest`**: `{ secret: string }` — `writeOnly`, ≤8192. The ONLY plaintext ingress.
- **`SetCredentialResponse`**: `{ role, status: 'configured', credentialId: 'cred_…' }` — never a secret.
- **`TestConnection`**: `{ checks: ConnectionCheckResult[] }`. **`ConnectionCheckResult`**: `{ check: 'repository_reachable'|'ticket_source_auth'|'repository_host_auth', status: 'pass'|'fail'|'skipped', detail: string }`.
- **Headers**: `createProject` / `updateProject` accept optional `X-Actor-Identity`; `createProject` accepts optional `Idempotency-Key`; `setProjectCredential` **requires** `Idempotency-Key`. `disable`/`enable`/`test-connection` take only the `projectId` path var.

### Architecture / patterns to mirror (do NOT reinvent)
