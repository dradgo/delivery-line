## Story

As a backend developer,
I want a write-only, encrypted credential store wired to the `CredentialCipher` and integrated with redaction,
so that per-project connector secrets persist encrypted at rest, are usable in memory only at connector-call time, and can **never** leak through logs, events, artifacts, or exports.

## Acceptance Criteria

> These ACs are **reconciled** against the live architecture boundaries, the actually-merged code (3c-4 done; 3c-6 uncommitted), and the absence of an export pipeline. Where the epic wording conflicts with an enforced invariant or unbuilt dependency, the reconciled wording below is authoritative (see Dev Notes → "Why these ACs differ from the epic").

1. **Set/get credential.** A `ProjectCredentialService` in `application.project` exposes `setCredential(String projectPublicId, ConnectorRole role, String plaintext)` — it encrypts the plaintext via `CredentialCipher.encrypt(...)` and persists `(ciphertext, keyId, algo)` to `project_credentials`; and `getDecrypted(String projectPublicId, ConnectorRole role)` → `Optional<String>` that reads the active row, decrypts via `CredentialCipher.decrypt(...)`, and returns the plaintext **in memory only** (never logged, never retained in a field).
2. **Write-only contract.** No API, service method, serialization path, DTO, or log line ever returns a stored secret — **plaintext or ciphertext** — to a client. The store exposes only `setCredential` (returns a non-secret "configured" status / the `cred_` public id) and the internal `getDecrypted` (for immediate connector use). `ProjectCredentialEntity.ciphertext` is never reachable by Jackson (no controller returns it; that surface is 3c-8). There is **no** `getCiphertext`-shaped read-back path.
3. **`ProjectCredentialSource` goes live + typed `ConnectorRole`.** `ProjectCredentialService` **implements** the 3c-3 `ProjectCredentialSource` seam (`resolveSecret(Project, String role)`), so `ProjectConnectorResolver.resolveConnectorSecret(...)` now returns real decrypted secrets at use-time. The new `ConnectorRole` enum (`TICKET_SOURCE("ticket_source")`, `REPO_HOST("repo_host")`) is introduced (R1) and the `String role` arriving through the seam is parsed to it via fail-fast registry parsing.
4. **Redaction coverage.** Project-credential fixtures are added to the **AR10 adversarial-secret fixture set** (`src/test/resources/redaction-fixtures/`) — a Linear-token-shaped, a GitHub-token-shaped, and an opaque-secret-under-a-`credential`-key fixture — proving `RedactionPolicyService.redact(...)` strips them across the log/event/artifact egress paths. The store's own surfaces emit no secret material (AC2).
5. **Export redaction (structural + regression).** Because **no export pipeline exists yet** (R4), AC4 is satisfied by: (a) the write-only store guarantees `project_credentials` ciphertext can never be serialized into an export; (b) a `redactForExport(...)` regression test proves a payload that *embeds* a credential value emits **no** secret material; (c) a clearly-marked forward note records that when epic-05 export lands it must exclude `project_credentials`.
6. **One-active-per-role + rotation.** Leveraging the V17 partial unique index `uq_project_credentials_project_role (project_id, connector_role) WHERE archived_at IS NULL`, `setCredential` **archives** the current active row (`archived_at := now()`) and **inserts** a fresh `cred_` row (new `keyId` from the cipher) in **one transaction** — replace-on-reset is idempotent and rotation appends a new `keyId` without ever exposing the old plaintext. The partial index (not a total UNIQUE) is what makes archive-then-reinsert legal.
7. **`connector_role` persistence boundary (handed off from 3c-6).** `PersistedRegistryValues.projectCredentialConnectorRole(String)` parses `project_credentials.connector_role` raw text → `ConnectorRole` with fail-fast `UNKNOWN_REGISTRY_VALUE`; it is registered in `RegistryContractTest.everyCurrentPersistenceBoundaryUsesUniformFailFastRegistryParsing`, and a drift assertion ties the V17 `ck_project_credentials_connector_role` CHECK value-set to `ConnectorRole` (R3).
8. **Foundation gate.** The credential-redaction assertion is added so a leak fails the gate (story 1.23). Concretely: the new AR10 credential fixtures flow through **Contract #9** (`RedactionAdversarialFoundationContract`, which reads the manifest) automatically; verify `-Pfoundation-gate verify` is green with the fixtures present.
9. **Boundary + error codes.** `application.project` calls only the `CredentialCipher` **port** (`application.security`) — never `infrastructure.crypto`; persistence goes through a new application-owned SPI port implemented in `adapters.persistence` (`application-cannot-import-adapters`). **No new `DomainErrorCode`**: a `setCredential` against a non-existent project surfaces the 3c-2-registered `PROJECT_NOT_FOUND`; cipher failures throw the unchecked `CredentialCipherException` (no REST mapping here — that is 3c-8). `ArchitectureBoundaryTest` is the gate.
10. **Tests.** Coverage asserts: set→getDecrypted round-trip **through the store** (Testcontainers IT); redaction of the credential fixtures across log/event/artifact + `redactForExport`; write-only enforcement (no read-back method exists / nothing serializes ciphertext); replace-on-reset (archive old + insert new, one active row remains); rotation appends a new `keyId`; `getDecrypted` returns empty for an unconfigured `(project, role)`; `ConnectorRole` fail-fast on a bad DB value. New credential classes meet **≥90%** line coverage (credential/sanitization bar, 3c-11 AC5).

### Cipher wiring (copy-ready)

```java
// application.project.ProjectCredentialService (@Service, implements ProjectCredentialSource)
EncryptedSecret enc = cipher.encrypt(plaintext);              // 3c-4 port, application.security
recordPort.archiveActive(projectPublicId, role, now);        // free the partial-index slot
recordPort.insert(new ProjectCredential(
    PublicIdPrefixes.PROJECT_CREDENTIAL.next(),               // cred_<32hex>
    projectPublicId, role,
    enc.ciphertext(), enc.keyId(), enc.algo(), now, null));   // 1:1 with V17 columns
// ...
String plaintext = cipher.decrypt(row.ciphertext(), row.keyId(), row.algo()); // in-memory only
```

- `CredentialCipher.encrypt` → `EncryptedSecret(byte[] ciphertext, String keyId, String algo)` (`algo` == `"AES-256-GCM"`, `keyId` == `"mk_"+12hex`). `decrypt` hard-rejects a non-active `keyId` and any tamper → `CredentialCipherException` (never partial plaintext). Both `EncryptedSecret` and your `ProjectCredential` **clone `ciphertext`** in/out. [Source: application/security/CredentialCipher.java; EncryptedSecret.java; story 3c-4 Dev Notes]

### Architecture / boundary guardrails

- `application.project` → `application.security` (`CredentialCipher` port) is **allowed** (same layer). `application.project` → `infrastructure.crypto` is a **hard ArchUnit failure** (`APPLICATION_MUST_NOT_DEPEND_ON_INFRASTRUCTURE`) — you never import the impl; Spring injects `EnvelopeCredentialCipher` where the port is required. Persistence is reached through the new `ProjectCredentialRecordPort` (application) implemented in `adapters.persistence` (`application-cannot-import-adapters`). [Source: ArchitectureRuleCatalog APPLICATION_MUST_NOT_DEPEND_ON_INFRASTRUCTURE + LAYERED_BOUNDARIES; story 3c-4 R1]
- `@Service` beans in `application..` must be named `*Service`/`*Orchestrator` (`APPLICATION_SERVICES_MUST_BE_NAMED_AS_SERVICES`) — `ProjectCredentialService` is fine; a `*Store`/`*Source` impl would need `@Component`. (`ProjectCredentialSource` is an interface, so the impl being `ProjectCredentialService` satisfies both.) [Source: story 3c-3 "ProjectConnectorResolver cannot be @Service" trap; ArchitectureBoundaryTest]
- New `@Service`/`@Component` beans must not break key-less `@SpringBootTest` contexts — the credential store has no startup DB read (unlike the 3c-4 guard) so it is inert until called; no profile gate needed. [Source: story 3c-4 guard pattern]

### Persistence pattern (template = `IntegrationLink*`)

- Entity/Repository/Mapper/Adapter quartet under `adapters.persistence{,.entity,.repository,.mapper}`. `IntegrationLinkPersistenceAdapter.insert` (lines 84-150) is the template: `PublicIdPrefixes.require`, `saveAndFlush`, `catch (DataIntegrityViolationException)` → constraint-name → typed `DomainException`, `MdcKeys.sanitizeForLog` on any externally-derived logged value, INFO on success with public ids only. Registry-enum columns are stored as raw `String` and parsed at the entity getter via `PersistedRegistryValues` (see `IntegrationLinkEntity` sync_status getter). `@PrePersist` defaults `created_at` to UTC. [Source: adapters/persistence/IntegrationLinkPersistenceAdapter.java:84-150; entity/IntegrationLinkEntity.java]
- Rotation/idempotency: do **not** add an idempotency-key column — the V17 **partial unique index** (`… WHERE archived_at is null`) is the single-active enforcement; archive-then-insert in one tx is the replace/rotate mechanism. A partial unique index is in `pg_indexes` (assert `indexdef`), not `pg_constraint contype='u'`. [Source: V17 migration:54-56; one-active-per-key partial-index review note]
