# Story 4.17: Integration Conflict Detection — Linear + GitHub vs Internal State

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a backend developer + workflow owner needing visibility into integration drift,
I want a scheduled `IntegrationConflictDetectionJob` that compares internal workflow state against external Linear ticket state + GitHub PR state, persisting detected conflicts to a queryable `integration_conflicts` table — never silent overwrite per NFR19,
so that FR41 (workflow owners can detect disagreement between internal workflow state and external integration state) is wired and FR43 (distinguish sync failures, link failures, state conflicts) is upheld.

## Context & Central Reconciliation (READ FIRST)

**This is the DETECTION half of Epic 4's integration-conflict pair. It is a PURE PRODUCER: it creates the `integration_conflicts` table, a scheduled sweep that writes rows, per-conflict `integration.conflictDetected` events, Prometheus metrics, and a read-only `listUnresolvedConflicts` query surface.** You do NOT build any reconcile/resolve path, any REST endpoint, any auto-pause, or any orchestration gate — those are stories **4.6** (`RecoveryService.reconcile`, reads `conflictId`, sets `resolved_at`/`resolved_by_action_id`) and **4.18** (operator-queue surfacing, `GET /api/v1/integration-conflicts`, conflict-driven pause + dispatch gate). Both are **`backlog` (not built)** — verified in `sprint-status.yaml:639,652`. The entire `integration_conflicts` / `IntegrationConflict*` namespace is **greenfield** (repo-wide grep = zero matches).

The closest end-to-end analogue to mirror is **story 3f-8's split-rollup reconciliation sweep** (a `@Scheduled`, `@ConditionalOnProperty`-gated, PG-advisory-locked, batch-bounded, archived-excluding reconciliation sweep with a configurable interval + main/test yaml mirror). Read `SplitRollupSweepConfiguration` + `SplitRollupReconciliationSweepService` + `RunSplitCompletionRollupService` for the exact house discipline. For the read surface + new-table+SPI split, mirror **story 3f-4's `SplitProposalService`** (read+write port split, typed nested-record view in the `application` package). For the registry work, mirror **`FailureCategory`** (a `RegistryValue` enum) and the `PublicIdPrefixes` / `WorkflowEventType` additions.

## Dev Notes

### Relevant architecture patterns and constraints

- **Sweep skeleton (mirror 3f-8).** `SplitRollupSweepConfiguration` (thin `infrastructure.config` trigger, `@EnableScheduling` scoped to the conditional config so the scheduler only spins up when enabled) → `SplitRollupReconciliationSweepService.sweep()` (batch-bounded, archived-excluded, WARN on `found==batchLimit`) → per-item `REQUIRES_NEW` tx that swallows+WARNs, with the PG advisory `pg_advisory_xact_lock` taken FIRST inside the tx. Copy this shape exactly; pick a fresh dedicated advisory-lock key (e.g. `"ICON"` = a 32-bit int) distinct from `RDEP` (`0x52444550`).
- **New-table + read-service split (mirror 3f-4).** `SplitProposalService` owns writes to one table + a decoded typed read view; SPI split into `SplitProposalReadPort` + `SplitProposalWritePort` (`application.workflow.spi`), impl in `adapters.persistence`. Read-view records (`SplitProposalView` + nested) live in the `application` package (NOT `.spi`) so REST/consumers map them without tripping the REST-stays-thin ArchUnit pin. For the archived/status-filtered list contract, mirror `ClarificationReadPort` (every method filters `archived_at IS NULL`; status-grouped; `created_at ASC` + id tiebreak).
- **Integration data model (Reconciliation 2/3/4/5).** `integration_links` columns: `public_id (ilk_)`, `workflow_run_id` (FK→`workflow_runs.id` surrogate; domain exposes `workflowRunPublicId`), `integration_type ∈ {linear, github_pr, internal_subtask}`, `external_ref`, `external_metadata jsonb` (entity: `Map<String,Object>` via `@JdbcTypeCode(SqlTypes.JSON)`; the persistence adapter owns `byte[]↔Map`), `last_sync_at`, `sync_status ∈ {linked,synced,stale,failed,superseded}`, `project_id` (V17, unsurfaced), `archived_at`. "Active" = `archived_at IS NULL AND sync_status != 'superseded'`. Cached GitHub baseline keys: `repositoryFullName, branch, commitSha, prNumber, prState, prUrl`. Cached Linear keys: `title, summary, authorIdentity, labels, ticketCreatedAt, ticketUpdatedAt, url` (NO state). The `sync_status` state machine forbids `failed→synced` directly (`failed→linked→synced`) — matters only if you rewrite metadata on a `failed` link.
- **Fresh-query adapters.** Ticket: `TicketSourceAdapter.fetchTicketByReference(TicketRef) → Optional<Ticket>` (`Ticket.sourceStatus()`/`sourceStatusId()` are the state; both nullable); throws classified `TicketSourceAdapterException.failureCategory()`. PR: `RepositoryHostAdapter.getPullRequestByRef(PullRequestRef) → Optional<PullRequest>` (`PullRequest.state()` = raw `open`/`closed` today; add `merged`); throws classified `RepositoryHostAdapterException.failureCategory()` + `.details()` (rate-limit `resetAtSeconds`). Existing on-demand precedent for a GitHub fresh-requery + metadata rewrite: `IntegrationLinkService.syncGitHubPr` (`:613-689`) — NOT scheduled; reuse its classification/rewrite shape, do NOT call it per-link (it locks + transitions).
- **Registries.** `RegistryValue` = single `value()`. `IntegrationFailureCategory` (REUSE) is NOT SQL-CHECK-backed and not in the API-placeholder manifest — it lives in logs/`DomainException` details. `IntegrationConflictCategory` (NEW) IS SQL-CHECK-backed (the table's `conflict_category`) → needs the `DomainRegistry` method + `RegistryContractTest` set-equality + CHECK-alignment assertions, but NO API placeholder in this story (4.18 adds the REST schema).
- **Events.** Non-lifecycle append via `WorkflowEventWritePort` (like `INTEGRATION_LINKED`), priorState==resultingState==null, `actorType=SYSTEM`. Reuse allow-listed detail keys; the only new keys are `conflictId`/`conflictCategory`.
- **Metrics.** Counter held in a service field (`ArtifactOperationService.idempotencyReplayCounter` idiom); gauge via a `@Component MeterBinder` with state in a strongly-referenced `volatile` field ([[micrometer-gauge-weak-ref-nan-flake]]); scrape catches `RuntimeException` and serves the last snapshot; cache one read per ~1s scrape window. Metrics are disabled in `@SpringBootTest` — re-enable per scrapeable IT ([[prometheus-actuator-disabled-in-springboottest]]).

### Logging Requirements (project-wide standard)

Every story is expected to leave the touched services observable enough to debug a production incident without re-deploying. This is enforced via the "Logging instrumentation" task above.

- **Framework:** SLF4J + Logback (Spring Boot default). No `System.out`, no `printStackTrace()`.
- **Where to log (minimum surface for this story):**
  - `IntegrationConflictDetectionService.sweep` → `INFO` on entry (types scanned, batchLimit) + `INFO` on exit (`SweepResult` fields, durationMs); per first-insert conflict `INFO` "integration conflict detected"; per dedup-skip `DEBUG`.
  - External-API failure → `WARN` with the `IntegrationFailureCategory.value()` + (for rate-limit) `resetAtSeconds`; the sweep-level rate-limit backoff `WARN` "backing off github conflict scan".
  - Per-link swallowed error inside `REQUIRES_NEW` → `WARN` with the link id + exception simpleName (mirror `RunSplitCompletionRollupService.rollupParent`).
  - Persistence insert of a conflict row → `INFO` "persisting integration_conflict" with `conflictId`/`conflictCategory`/`integrationLinkId`.
- **Required context keys:** `correlationId` (per sweep), `workflowRunId`, `integrationLinkId`, `integrationType`, `conflictId`, `conflictCategory`, `failureCategory` (on skips).
- **Forbidden in log output:** GitHub/Linear tokens, PR bodies, raw external JSON payloads, any redacted field — only ids/refs/states.
- **Test contract:** pin the sweep-summary line, a first-insert line, and the rate-limit-backoff `WARN` with `OutputCaptureExtension` (or list-appender).
