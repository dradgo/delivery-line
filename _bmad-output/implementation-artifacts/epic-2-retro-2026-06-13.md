## 4. Challenges & Growth Areas

### 4.1 Real end-to-end loop never ran — *Alex's chosen biggest pain* (see Significant Discovery §6)

The full ticket-implementation cycle (ticket → spec → approve → agent execution → impl plan → PR → review) is built in pieces but **dormant at the integration seams**. We have a UI over a loop that has never completed once against real git/GitHub data.

### 4.2 Frontend dev-loop cross-platform friction persisted all epic

CI parity was solved (A5), but the *inner loop* stayed painful: lockfile native-binding mismatches (Vite/rolldown), TS6 `legacy-peer-deps`, OpenAPI regen needing a shell switch, WSL2-for-Linux-repro, Windows `node.exe` hijacking the PATH. We fixed "does it build in CI," not "can a dev iterate on Windows without losing an afternoon."

### 4.3 CI gate cascades

One unformatted Prettier file fails `format-static-checks` → `doctor-smoke` → every downstream job skips. The red job name is not the real failure — cost real debugging time repeatedly.

### 4.4 Backend-wire ↔ frontend-type drift

Generated `WorkflowDetail` TS types said `?: string` but the wire serialized JSON `null` — caused the "Something went wrong" crash on Investigating runs. Codegen told a half-truth; the UI trusted it. Will recur on every nullable artifact field in Epic 3.

### 4.5 Test-infra subtleties / flakes

`useLiveAnnouncement` defers one render (announcer lags `data-queue-state`); Vitest shares a module registry per worker so cross-file `vi.mock` of the same module races. Both now documented in memory — but each cost a flake-hunt because the guidance (A6) was never written.

### 4.6 Epic large enough to restructure twice

32 stories needed the 2a/2b split (2026-05-26), then a de-facto re-scope (2026-06-12), and absorbed 3-30 from Epic 3. (Per Alex: the active-slice/`next-active` mechanism itself is working fine — see §7.)

## 6. Significant Discovery — Epic 3 Plan Impact

**Discovery (Alex, Project Lead):** The full ticket-implementation cycle has **never run for real.** Epic 2 delivered the UI surface; the live loop underneath is unproven because the integration seams are dormant:

- Repo content is composed **before** the clone — `repositoryRef` seam unset by the broker ([[repo-seam-dormant-bundle-before-clone]]).
- `ArtifactOperationService.markAvailable` has **no production caller** — runner-ingested artifacts stay `pending` ([[markavailable-has-no-production-caller]]).
- The pr-output `prRef` validator accepts only `PR-<n>`/URL but the real GitHub adapter emits `owner/repo#number` — latent false-`Failed` ([[proutput-prref-validator-rejects-real-adapter]]).
- Stale hand-built runner `:latest` images exit 20; the full real-run enablement chain (fresh image, creds, trust/sandbox flags, bridge network, CA certs) must be verified ([[runner-image-stale-causes-exit-20]]).

**Impact on Epic 3:** Epic 3a/3b stories are sequenced by component, not by "prove one real run." Our green tests pass against mocks and dormant seams, which is why they don't reassure on pilot-readiness.

**Decision (Alex confirmed):** Elevate a **"first real full-cycle run"** to Epic 3's **pilot-readiness gate** — activate the dormant seams and demonstrate one real ticket implemented end-to-end before adding more breadth. See C1–C3.

## 10. Key Takeaways

1. **We shipped the product's face** — a real web UI over the PM loop. Biggest visible step since the project began.
2. **The body underneath is unproven** — the real ticket-implementation cycle has never run end-to-end; the seams are built but dormant. This is Epic 3's gating job (C1–C3).
3. **We apply lessons but don't write them down.** Three Epic-1 doc commitments (A1/A6/A9) went unwritten and the avoidable flakes recurred exactly there. Re-committed into Epic 3b (B1–B3); "done" means the file exists.
4. **Architectural foresight compounds** — the generalized-composite bet and the registry/idempotency patterns keep paying out one epic later.
5. **CI parity ≠ dev-loop parity.** We solved the gate; the inner loop on Windows is still rough.
