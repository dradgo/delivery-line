# Story 4.21: Compare Mode Mobile Bounded State (UX-DR23)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a Product Manager / Developer occasionally needing Compare Mode on mobile (Galaxy S23+ class per UX-DR24),
I want Compare Mode to render as a **dedicated bounded mobile state** per UX-DR23 — a full-screen single-column takeover with an explicit before/after toggle rather than a compressed side-by-side,
so that the mobile review flow stays usable (and comprehensible) when revision verification is needed away from desktop.

## Context & Central Reconciliation (READ FIRST)

**This is a PURE-FRONTEND story. There is NO backend slice at all.** Everything the backend must provide already shipped:

- The `enter_compare_mode` allowed-action + the `appendCompareOverlay` matrix surfacing — shipped in **story 4.20** (`AllowedAction.ENTER_COMPARE_MODE`, in the placeholder JSON + pinned).
- The `RevisionDelta` typed contract + `GET /api/v1/artifacts/{artifactIdA}/compare/{artifactIdB}` endpoint — shipped in **story 4.19**, LIVE in `schema.d.ts`.
- The prior-version id source (`ArtifactDetail.parentArtifactId`) that makes the compare fire against a real baseline — shipped in **story 4.20's code-review** (OQ-2 resolved "build now").

So do **NOT** touch Java, `openapi.json`, `schema.d.ts`, the `AllowedAction` enum, the query hooks, the query key, `compareView.ts`, or the route wiring in `$artifactId.tsx`. **The single job of this story is: at the mobile breakpoint, `CompareMode` renders a dedicated single-column bounded layout instead of the desktop/tablet side-by-side/stacked composite.** Everything else is reused unchanged.

The most important thing to internalize: **story 4.20 explicitly DEFERRED the mobile bounded state to this story** (its Scope Boundary table row: "Mobile bounded state (dedicated single-column, before/after toggle) — **DEFER** — story 4.21 (UX-DR23)"). And **`RESPONSIVE.md` §3 already documents the exact mobile UX pattern this story must honor** ("This is a reservation, not an implementation… Epic 4 must honor [it]"). This story turns that reservation into code.

### HEADLINE RECONCILIATIONS (epic AC text vs live code — these bindings win)

1. **THE CENTRAL BINDING — the desktop/tablet `CompareMode` composite ALREADY EXISTS and is DONE (story 4.20); this story adds a mobile branch, it does not rebuild the composite.** `components/CompareMode.tsx` is the presentational composite (side-by-side for spec/plan, stacked file accordions for prOutput, summary-first toggle, J/K/Esc nav, the six `data-compare-state`s). It is prop-driven + fixture-tested, fed by the thin `CompareModeContainer` (which owns `useRevisionDelta` + `resolveCompareState`). **The mobile bounded state is a NEW render branch of the SAME presentational component (or a dedicated presentational sibling it dispatches to), selected by a viewport prop.** All the resolved-state plumbing (`CompareState`, `CompareView`, `normalizeRevisionDelta`, the per-block renderers) is reused verbatim. [Source: `deliveryline-frontend/src/features/workflows/components/CompareMode.tsx:228-813`; `CompareModeContainer.tsx:34-101`; `compareView.ts:86-290`; `4-20-compare-mode-ui-component-ux-dr13.md` Scope Boundary "DEFER" row]

2. **The breakpoint decision routes through the CANONICAL `useResponsiveLayout()` hook — NEVER an ad-hoc `window.matchMedia` / CSS media query (AC1 / `RESPONSIVE.md` AC8).** `hooks/useResponsiveLayout()` returns `'mobile' | 'tablet' | 'desktop'`: **mobile = 320–767px, tablet = 768–1023px, desktop ≥1024px** — the single source of the `768`/`1024` boundaries in the whole app. The mobile bounded state activates iff `useResponsiveLayout() === 'mobile'`. **The CONTAINER calls the hook** (it is the query/hook-owning seam) and passes the resolved viewport down as a prop, so the presentational `CompareMode` stays router/query/matchMedia-free and its fixture tests just pass the prop. **This mirrors `ReconciliationDialog` (story 4.23) EXACTLY** — `const isMobile = useResponsiveLayout() === 'mobile'` at the dialog top, threaded down as `isMobile` to a body that switches `grid-cols-2` → `grid-cols-1`. Follow that precedent. [Source: `hooks/useResponsiveLayout.ts:26-87`; `components/ReconciliationDialog.tsx:42,105,228-231,276,398-402`; `RESPONSIVE.md` §1 (breakpoint matrix) + §5 (`@/test/matchMedia`)]

3. **`NEVER` shrunk side-by-side on mobile (AC6) — the mobile body MUST NOT render the 2-column `compare-synced-scroll` / the `grid-cols-2` region detail / the desktop stacked layout.** UX-DR23's structural-collapse rule is literal: "compare should become a dedicated bounded mobile state rather than a compressed side-by-side layout." The desktop composite's default state renders a 2-col prior|current grid (`SideBySideRegion` → `grid grid-cols-2`) inside a single scrollport (`data-testid="compare-synced-scroll"`). **At mobile that entire surface is replaced by a single-column, one-revision-at-a-time body.** A layout test MUST assert the mobile render shows only one revision at a time and `compare-synced-scroll` / `grid-cols-2` region details are absent. [Source: `CompareMode.tsx:526-542` (the synced-scroll 2-col surface), `:697-722` (the `grid-cols-2` region detail); UX spec "Structural Collapse Rules" line 2372; `RESPONSIVE.md` §3]

4. **The mobile layout is a FULL-SCREEN TAKEOVER covering the AppShell nav rail + context panel (AC1).** Compare Mode is mounted as an in-context overlay INSIDE the main pane (`$artifactId.tsx` renders `<CompareModeContainer>` inside `<Stack>` — story 4.20 AC8, no new route). On desktop/tablet it is a plain in-flow panel. On **mobile** the bounded state must escape the main-pane flow to cover the whole viewport (nav rail + context panel + the artifact-route chrome). Provisional binding: a `fixed inset-0 z-<overlay>` full-screen layer with `bg-surface` + its own scroll container — NOT a Radix `Sheet`/`BoundedDetailSheet` (those are for secondary detail drawers; a full compare takeover is its own top-level layer, and the desktop compare is already a plain panel, not a Radix overlay). Confirm the z-index tier + whether to lock body scroll (OQ-1). [Source: `routes/workflows/$workflowRunId/artifacts/$artifactId.tsx:94-138` (in-context mount inside the main-pane `<Stack>`); `RESPONSIVE.md` §3 ("dedicated full-screen state")]

5. **Before/after toggle (AC2, AC5) — a prominent, always-visible top-bar control that switches WHICH revision the single column shows; it is NOT a menu item.** State: `useState<'before' | 'after'>` (i.e. show revision A/prior vs revision B/current). Provisional default = **`after` (B / current)** — the artifact under review is the current version, so open on it and let the user flip to "before". The toggle must be keyboard-operable (a real `<button>`/segmented control, not a hover affordance) and tap-target ≥44×44 (see Reconciliation 7). For **spec/plan** blocks the toggle drives which side renders (before → `priorText`/`priorStepText`; after → `currentText`/`currentStepText`). For **prOutput** the per-file unified diff already IS the before/after within one view, so the toggle is de-emphasized/hidden for prOutput (a file diff is not per-revision) — confirm (OQ-2). [Source: epic-04-recovery.md Story 4.21 AC2/AC5; `CompareMode.tsx:701-720` (the prior vs current cell dispatch to reuse); `compareView.ts:34-62` (block field shapes)]

6. **Prev/Next change buttons (AC3) REPLACE J/K on mobile — reuse the existing region-jump machinery.** J/K are impractical without a keyboard, so mobile surfaces on-screen "Previous change" / "Next change" buttons in the top bar that advance to the next changed region in the currently-displayed revision. The desktop composite already has the `regionRefs` + `goToRegion(index)` + `jump(direction)` + `compareJumpedToRegion(i, total)` announcement machinery (`CompareMode.tsx:265-305`) — **reuse it**; the mobile buttons call the same `jump(+1)`/`jump(-1)`. The region refs must point at the single-column block anchors that are actually rendered for the current toggle side. [Source: `CompareMode.tsx:265-305` (jump machinery), `:626-647` (the existing desktop jump buttons to mirror)]

Only `GovernedButton` carries them by default. **Every interactive mobile control (before/after toggle, prev/next, exit X) MUST carry `min-h-touch` (and `min-w-touch` for icon-only) via `className`, OR use `GovernedButton`.** The desktop compare uses `size="sm"` (32px) buttons — that is fine for desktop but is a REGRESSION if copied to mobile. Add a static class-presence assertion mirroring `src/test/a11y/touch-target.test.tsx`. [Source: `components/ui/button.tsx:20-25` (the sub-44 sizes); `src/test/a11y/touch-target.test.tsx:17-34` (the `toHaveClass('min-h-touch')` idiom); `docs/testing/responsive-real-device-checklist.md:71-77` (the live 44px verification)]

The dispatch is strictly `useResponsiveLayout() === 'mobile'` → mobile body; `'tablet'`/`'desktop'` → the existing 4.20 body (byte-identical). Do NOT alter the desktop/tablet render path. [Source: epic-04-recovery.md Story 4.21 AC9; `useResponsiveLayout.ts:45-56`]
