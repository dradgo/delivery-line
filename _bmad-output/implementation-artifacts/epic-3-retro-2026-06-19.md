## 3. Successes & Strengths

### 3.1 The Epic-2 pilot gate is closed — *Alex's #1 from last retro*
C1/C2/C3 all delivered. Dormant seams activated: `ArtifactOperationService.markAvailable` wired (3a-9 / 3b-3), real `:latest` runner image rebuilt (was a mock build), repo content materialized via backend-owned `captureAndPush` (backend owns git, not the runner). A real ticket reached a merge-ready PR + developer review. **The body underneath the Epic-2 UI is now proven.**

### 3.2 The real run earned its keep as a bug-finder
Exactly as Epic 2 predicted ("green-against-mocks won't reassure on pilot-readiness"), the real run surfaced a cascade of latent defects no mock could expose — all fixed 2026-06-19:
- **prRef / drift validation gates structurally unsatisfiable** — the broker validated runner-reported git refs that are placeholders the backend overwrites (`captureAndPush` owns the branch/commit/PR). A genuine *design error*, not a typo — only a real run could reveal it.
- context-bundle 2KB payload cap (twin of the runner-result cap) — pr-output bundle exceeded it.
- Codex read-only sandbox blocked by Docker's default seccomp (bubblewrap userns) → `security-opts: [seccomp=unconfined]`.
- recovery bar requesting the wrong allowed-actions role (product_reviewer vs workflow_owner).
- the local `:latest` image was silently a **mock** build (ticket-blind canned artifacts).

### 3.3 The generalized-composite bet paid out a *third* time
3-26/3-27/3-28 added impl-plan / PR / impl-review **variants** of the Epic-2 Artifact Review Panel + Decision Bar — 3b-4/3b-5/3b-6 wired them as variants, not reshapes.

### 3.4 Vendor-neutral seams built before they were needed
3-32 (`TicketSourceAdapter`, extracted from LinearAdapter) + 3-33 (`RepositoryHostAdapter`, extracted from GitHubAdapter) — clean symmetric abstractions that are Epic 3c's foundation.

### 3.5 Adversarial review held under load — and caught itself
Multiple high/medium leads were *disproven against live source* by the Edge-Case / Acceptance layers (3-34 "fail-open gate", 3-35 "silent no-op XSS keys"). The process caught its own false positives.

## 6. Significant Discovery — Epic 4 Plan Impact

**Discovery:** Epic 3's biggest lesson is that **real runs surface failures mocks cannot** (§3.2). Epic 4 is a *failure / recovery* epic. A recovery epic validated only against *synthetic* failures would walk straight back into the mock trap — amplified, because the entire epic is *about* failure modes.

**Warning sign:** this very session we found the recovery bar requesting the wrong role — right as Epic 4 prepares to lean hard on the recovery / Decision Bar surface (`recovery_operator` mode).

**Recommendation (decision deferred to Epic 4 planning, per Alex):** consider making "one real failure recovered end-to-end" Epic 4's pilot gate — drive retry / resume / reconcile against the *actual* failed runs the live loop already produces, mirroring the C1–C3 win. **Epic update required:** No — but log this as headline input to Epic 4 sprint planning.

## 10. Key Takeaways

1. **The loop runs for real.** Epic 2's central gap — a UI over a loop that had never completed once — is closed. A real ticket reached a real merge-ready PR and developer review.
2. **The real run was the best tester we have.** It found a cascade of design-level defects (the prRef gate chief among them) that four epics of green mock tests never surfaced. "Mocked green ≠ pilot-ready green" is now proven, not theorized.
3. **Hard done, easy deferred.** The hard real-run gate (C1–C3) was nailed; three trivial markdown docs (B1–B3) slipped a third epic. The content survived in memory — but memory then overflowed its limit. Fixing this is D1–D4, before Epic 4.
4. **Architectural foresight keeps compounding** — generalized composites (third payout) and the vendor-neutral adapters (3-32/3-33) are paying forward into Epic 3c and 4.
5. **Epic 4 must not re-enter the mock trap.** A recovery epic tested only on synthetic failures repeats Epic 3's mistake, amplified — drive recovery against real failed runs (decide at planning).
