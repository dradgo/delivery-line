# Story 3l.1: Project-Memory Read Model — Projection over Lineage / Deps / Links / Artifacts

Status: ready-for-dev

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an authorized user,
I want a project's tickets, runs, and artifacts organized into a single navigable graph of how they relate — projected read-only from the relational data that already exists,
so that the scattered lineage / dependency / integration-link / produced-artifact data becomes one project-scoped **memory** the later stories (3l-2 asserted edges, 3l-3 query + graph view, 3l-4/3l-5 agent context) can query, visualize, and feed back to agents — without any new write-path for relationships that already exist.

## Context & Central Reconciliation (READ FIRST)

**This is a pure READ-ONLY, backend-only, application-layer story — the foundation projection of Epic 3l Part A.** You add ONE new `application.memory` package containing a `ProjectMemoryService` (`@Service`, `@Transactional(readOnly = true)`) plus the graph view records (`ProjectMemoryGraph` / `MemoryNode` / `MemoryEdge` and their two typed enums); you add ONE new SPI read port (`ProjectMemoryReadPort` in `application.memory.spi`) with a batched, project-scoped, native-SQL persistence adapter (`ProjectMemoryPersistenceAdapter` in `adapters.persistence`); you add one ArchUnit confinement rule + one JaCoCo per-package floor; and you add unit + real-PG tests. **You do NOT add any REST endpoint, CLI command, FE view, OpenAPI/`schema.d.ts` change, Flyway migration, `WorkflowState`, `WorkflowEventType`, `AllowedAction`, `RunnerStage`, `DomainErrorCode`, or registry value.** The query surface (REST + CLI + FE graph/timeline) is **story 3l-3**; the one new write table (`project_relations` + `RelationType`) is **story 3l-2**; agent-context retrieval is **3l-4/3l-5**.

The single most important thing to internalize: **the epic lists six edge kinds and calls all six substrates "done," but two of them do not exist in the codebase yet.** `sentry_bug` (3i-4) and `profile` (3j `workflow_profile`) are **`backlog`** — Epic 3i and Epic 3j have not been built (verified: zero `sentry`/`workflow_profile` hits repo-wide; `sprint-status.yaml` shows `epic-3i: backlog`, `epic-3j: backlog`). This story therefore projects the **four edge kinds that have live persistence today** and defines the other two as **dormant, forward-wired enum values** so 3i-4 / 3j can light them up later without touching this story's model. The **binding clarifications below win** over the epic phrasing — the same house discipline stories 4.1 and 4.19 established.

### HEADLINE RECONCILIATIONS (epic AC text drifts from live code — these bindings win)

1. **THE CENTRAL BINDING — only FOUR of the six edge kinds have a live substrate; `sentry_bug` and `profile` are BACKLOG.** Epic AC1/AC4 name six `edgeKind`s and the epic's "Prerequisites & reused substrates (all done)" lists Sentry→bug (3i-4) and `workflow_profile` (3j) among them. **Both are unbuilt.** [Source: `sprint-status.yaml:603` `epic-3i: backlog`, `:607` `3i-4-sentry-error-source-connector: backlog`, `:611` `epic-3j: backlog`, `:612` `3j-1-workflow-profile-...: backlog`; whole-repo grep for `sentry` and `workflow_profile` in `deliveryline-backend/src/main` = 0 hits.] **Binding:** the `MemoryEdgeKind` enum declares **all six** wire values (`split_lineage`, `run_dependency`, `integration_link`, `produced_by`, `sentry_bug`, `profile`) so AC4's typed-filter vocabulary is complete and forward-compatible, **but the projection emits only the four LIVE kinds** (`split_lineage`, `run_dependency`, `integration_link`, `produced_by`). `sentry_bug` and `profile` are **dormant forward-slots** — documented, never emitted today, wired by 3i-4 / 3j when their columns land. Tests seed + assert the four live kinds and assert the two dormant kinds produce **no edges and no error**. (See OQ-1: Alex may prefer to defer this story until 3i/3j land — provisional binding is build-now-over-four.)

2. **`workflow_profile` is not a column anywhere — it cannot type nodes/edges yet.** Beyond edge kind #6, the epic uses `workflow_profile` as node metadata (bug↔feature). There is **no such column** on `workflow_runs` (or any table) and no entity field. [Source: `adapters/persistence/entity/WorkflowRunEntity.java` — no profile field; no migration adds it.] **Binding:** do NOT read or surface a profile; the `profile` edge/typing is dormant (Reconciliation 1). No node carries a profile attribute in 3l-1.

3. **Node ids are ALWAYS `public_id` / `external_ref` — never the `bigint` PK. Bridge the two key-spaces in SQL.** `workflow_runs.parent_run_id` (V27) and `run_dependencies.run_id` / `depends_on_run_id` (V28) reference `workflow_runs.public_id` (**text**). But `integration_links.workflow_run_id` and `artifacts.workflow_run_id` reference `workflow_runs.id` (**bigint**). [Source: `V27__add_parent_run_id_and_split_state.sql:4-9`; `V28__add_run_dependencies...sql:8-15`; `V1__create_workflow_core_tables.sql:106,239,249` (bigint FKs).] **Binding:** the native-SQL projection joins `integration_links`/`artifacts` back to `workflow_runs` on the bigint FK and SELECTs `workflow_runs.public_id`, so every emitted node id is `run:<run_...>` / `artifact:<art_...>` / `ticket:<external_ref>`. A raw bigint must never leak into a node id (AC3).

4. **There is NO artifact `title` column — the artifact node label is `artifact_type` (+ `version`).** The `artifacts` table has no `title`/`name` column; an artifact is `public_id` (`art_…`) + `artifact_type` (registry enum) + `version`. [Source: `V1__create_workflow_core_tables.sql:103-135`; `adapters/persistence/entity/ArtifactEntity.java:30-41`.] **Binding:** artifact node id = `artifact:<public_id>`, label = `"<artifactType> v<version>"` (e.g. `spec v2`). AC3's "artifact title" reconciles to `artifactType`. **Never** touch `ArtifactPayloadStore` — bodies stay out of the projection (AC3 "ids only, no artifact bodies inlined").

5. **Artifact→artifact lineage (`parent_artifact_id`) is NOT an edge kind in 3l-1.** AC4's six `edgeKind`s do not include an artifact-lineage edge; artifacts appear as **`produced_by` leaves** hanging off their producing run (`run → artifact`), not chained to each other. [Source: AC4 vocabulary; `artifacts.parent_artifact_id` exists (`V1:109`) but is out of this story's edge set.] **Binding:** emit only `produced_by` (run→artifact); do not walk `parent_artifact_id`. (The artifact revision chain is 4.19 Compare-Mode territory, not the memory graph.)

6. **PR is NOT a node — node kinds are ticket / run / artifact only.** The epic says `integration_links` binds "ticket↔run↔PR," but AC3 fixes node kinds to **ticket, run, artifact**. [Source: AC3.] **Binding:** the `integration_link` edge binds `ticket → run` (the `linear` link type). `github_pr` links do **not** mint a PR node (no PR node kind); the PR ref is out of 3l-1 scope (a documented forward option). Filter integration-link rows to `integration_type = 'linear'` for edge/ticket-node emission.

7. **No new REST / CLI / FE / OpenAPI / Flyway / registry in 3l-1 — the service is exercised only by tests.** The projection is invoked as `ProjectMemoryService.projectMemory(projectId) → ProjectMemoryGraph`; 3l-3 wires it to REST + CLI + the FE graph/timeline. [Source: epic §"Sub-sequence Part A before Part B" — 3l-1 = foundation projection, 3l-3 = query surface.] The Flyway head is **V33** (`V33__add_build_stage_columns.sql`); **do NOT add a migration** — the one new table (`project_relations`) is **3l-2's V34**, not this story's. No `DomainErrorCode` (this story has no error surface of its own).

8. **Avoid N+1 with a batched native-SQL projection port (mirror `OperatorRunReadPort`), NOT per-run calls to existing snapshot ports.** Fanning `WorkflowRunReadPort.findByParentRunId` / `RunDependencyPort.graphView` / `IntegrationLinkService.findActiveTicketOriginView` / `ArtifactRecordPort` **per run** is an N+1 across the project's runs and violates AC5. **Binding:** add a dedicated `ProjectMemoryReadPort` whose adapter runs **~4 set-based, project-scoped, index-backed queries** (runs; run-dependencies; integration-links; artifacts) and returns flat row snapshots the service assembles. This is the exact shape of the closest existing precedent — `OperatorRunReadPort` + `OperatorRunPersistenceAdapter` + `OperatorRunRowSnapshot` (cross-table read-only aggregate). [Source: `application/workflow/spi/OperatorRunReadPort.java`; `adapters/persistence/OperatorRunPersistenceAdapter.java`.]

9. **Bounded node/edge ceiling — and NO silent truncation.** AC5 requires a bounded ceiling. **Binding:** cap the projection with a configurable ceiling (default via `@Value("${deliveryline.memory.node-ceiling:1000}")` — a plain injected default, NOT a validated `@ConfigurationProperties` record, to dodge the [[validated-config-needs-test-yaml]] fan-out); when the cap is hit, set `ProjectMemoryGraph.truncated = true` and `log.warn` the drop with counts. A silently truncated graph that reads as "complete" is a bug ([[code-review-diff-omits-untracked-new-files]] "no silent caps" discipline).

10. **Redaction posture = reuse the already-redacted `ticketTitle` snapshot; do not re-plumb redaction.** AC7 says node labels pass "the same content posture as the already-exposed `ticketRef`/`ticketTitle`." The ticket `title` is **already redacted at write** (`SHAREABLE_REDACTED`) into `integration_links.external_metadata` (3g-1). [Source: `application/integration/IntegrationLinkService.java:918-930` (`metadata.put("title", …)` through the redaction pass); read-back decode `findActiveTicketOriginView`/`metadataString` `:826-853`.] **Binding:** decode the `title` key from `external_metadata` in the adapter (mirror `metadataString`) — the value is already redacted, matching 3g-1's read posture exactly. Run-state and artifactType labels are registry enum values (inherently safe). Logs carry ids/lengths only (`MdcKeys.sanitizeForLog`), never titles.

## Acceptance Criteria

> From `epic-03l-project-memory-artifact-lineage.md` §"Story 3l-1" (lines 47–56), with **binding clarifications** in **bold parentheticals**.

1. **Given** a `ProjectMemoryService` in `application.*`, **Then** it projects — for a given `projectId` — a graph of **nodes** (tickets, runs, artifacts) and **edges** from **existing** persistence only: split lineage (`parent_run_id`, 3f-2), run dependency (`run_dependencies`, 3f-3), integration link (`integration_links` ticket↔run↔PR), `produced-by` (run→artifact), Sentry→bug (3i-4), and bug↔feature profile typing (`workflow_profile`, 3j). No new write-path — pure read-side projection. **(RECONCILED — new `@Service` `org.dradgo.application.memory.ProjectMemoryService.projectMemory(String projectId) → ProjectMemoryGraph`, `@Transactional(readOnly = true)`, invoked by tests only (query surface = 3l-3). Of the six edge kinds, only FOUR are LIVE — `split_lineage` / `run_dependency` / `integration_link` / `produced_by`; `sentry_bug` (3i-4) and `profile` (3j) are BACKLOG and are dormant enum slots that emit no edges — Reconciliation 1/2. `integration_link` binds `ticket→run` for `linear` links only; PR is not a node — Reconciliation 6. `produced_by` = run→artifact; artifact→artifact lineage is out of scope — Reconciliation 5.)**

2. **Given** project scoping, **Then** every node and edge is scoped to the requested project via the existing indexed `project_id` FK on runs; a node/edge belonging to another project is never returned (cross-project leakage is asserted against). **(Scope on `workflow_runs.project_id` — index `idx_workflow_runs_project_id` [V17]. Every node originates from an in-project run; a `run_dependency` edge is emitted only when BOTH endpoints are in-project; `split_lineage` only when the parent is in-project. `projectId` is the project `public_id` (`prj_…`). Archived runs are EXCLUDED by default, mirroring `WorkflowRunReadPort.listRuns` + the 3f-8 discovery-excludes-archived rule — OQ-2. A cross-project-leakage IT seeds two projects and asserts the other's runs/links/artifacts never appear.)**

3. **Given** a node model, **Then** each node carries a stable typed id (`ticket:<ref>` / `run:<publicId>` / `artifact:<id>`), a kind, and a minimal label (ticket title from 3g-1 `external_metadata`, run state, artifact title) — ids only, no artifact bodies inlined. **(`MemoryNode(String id, MemoryNodeKind kind, String label)`. Ids: `run:<workflow_runs.public_id>`, `artifact:<artifacts.public_id>`, `ticket:<integration_links.external_ref>` — NEVER the bigint PK, Reconciliation 3. Labels: TICKET → decoded redacted `external_metadata.title`, null-safe fallback to `external_ref`, Reconciliation 10; RUN → `current_state`; ARTIFACT → `"<artifact_type> v<version>"`, Reconciliation 4 (no title column). A run/ticket/artifact appears as exactly ONE node even when it has many edges — dedup by node id. NEVER read `ArtifactPayloadStore` — ids/types only.)**

4. **Given** an edge model, **Then** each edge carries `from`, `to`, and a typed `edgeKind` (`split_lineage`, `run_dependency`, `integration_link`, `produced_by`, `sentry_bug`, `profile`) so consumers can render and filter by relationship type. **(`MemoryEdge(String from, String to, MemoryEdgeKind edgeKind)` where `from`/`to` are node ids. `MemoryEdgeKind` declares ALL SIX wire values (snake_case via a `value()` accessor) so 3l-3's filter contract is complete — but only the four LIVE kinds are ever emitted, Reconciliation 1. Directions: `split_lineage` parent-run → child-run (`parent_run_id`); `run_dependency` dependent-run → prerequisite-run (`run_id` → `depends_on_run_id`); `integration_link` ticket → run; `produced_by` run → artifact. Document each direction in Javadoc.)**

5. **Given** the read-path budgets, **Then** the projection stays within NFR25/NFR26 read-path budgets — reuses existing indexes (`project_id`, `parent_run_id`, the `run_dependencies` PK, `integration_links`) and adds no N+1 fan-out (join-fetched / batched), with a bounded node/edge ceiling per project. **(Implement via `ProjectMemoryReadPort` + native-SQL `ProjectMemoryPersistenceAdapter` — ~4 SET-BASED, project-scoped queries (runs; run_dependencies; integration_links; artifacts), NO per-run loop, Reconciliation 8. Indexes reused: `idx_workflow_runs_project_id` [V17], `idx_workflow_runs_parent_run_id` [V27], `idx_run_dependencies_run_id`/`_depends_on_run_id` [V28], `idx_integration_links_workflow_run_id_integration_type_created_at` [V1], `idx_artifacts_workflow_run_id_artifact_type_version` [V1] — NO new index (mirrors 4.1's "1000-run ≤5s on V1 indexes, no V34"). Ceiling via `@Value("${deliveryline.memory.node-ceiling:1000}")` `LIMIT`; over-cap → `truncated=true` + WARN, Reconciliation 9. A real-PG IT seeds a ≥ pilot-size project and asserts wall-clock under the NFR26 5s budget + query count is O(1)-in-runs.)**

6. **Given** parity, **Then** a project with no splits, dependencies, Sentry links, or extra profiles still projects a valid (sparse) graph — only the integration-link + produced-by edges that already exist — and a pre-3l project is byte-identical in every other read path (additive, read-only). **(A project with only runs+links+artifacts yields those nodes + `integration_link`/`produced_by` edges and an empty split/dependency set — no crash, no null. The new `application.memory` package touches no existing read path — every existing DTO/endpoint is byte-identical. An empty project → `ProjectMemoryGraph` with empty node/edge lists, `truncated=false`.)**

7. **Given** redaction, **Then** node labels and metadata pass the same content posture as the already-exposed `ticketRef`/`ticketTitle`; logs carry ids/lengths only. **(Ticket label = the already-`SHAREABLE_REDACTED` `external_metadata.title` decoded like `IntegrationLinkService.metadataString` — Reconciliation 10; no NEW redaction pass, no `ArtifactPayloadStore`. Run-state / artifactType are registry enum values. Logs: `MdcKeys.sanitizeForLog`, ids + counts only, never a title.)**

8. **Given** tests, **Then** coverage asserts: the graph assembles **every LIVE edge kind** from seeded fixtures; project scoping (no cross-project leakage); sparse-project parity; ids-only node labels; read-path budget (no N+1); `application.memory` ≥ 80% line coverage. **(Unit `ProjectMemoryServiceTest` (mock `ProjectMemoryReadPort`): all four live edge kinds assemble; node dedup; ids are public_id/external_ref not bigint; the two DORMANT kinds (`sentry_bug`/`profile`) emit nothing and don't throw; ceiling → `truncated=true`. Real-PG `ProjectMemoryProjectionIT` (`*IT`, Testcontainers): seed a project with split parent/child + a run-dependency + a linear ticket link + produced artifacts, assert all four edges + node labels; a 2nd project asserts NO cross-project leakage; a sparse project asserts parity; a ≥ pilot-size fixture asserts the AC5 budget + bounded query count. Add the `application.memory` per-package JaCoCo 0.80 floor.)**

### Relevant architecture patterns and constraints

- **Read-model service pattern (mirror `WorkflowInspectionService`).** `@Service`, "read-only: never mutates state," `final` ports constructor-injected with `Objects.requireNonNull`, read methods `@Transactional(readOnly = true)`, nested/sibling public `record …View`/graph records for projection, MDC scope idiom (`MdcKeys.beginScope`/`endScope`). [Source: `application/workflow/WorkflowInspectionService.java:85,125-165,231,507-541`.] Optional ports elsewhere use `@Autowired(required=false)` setters — 3l-1 needs only ONE mandatory port so a plain constructor is fine.
- **Reach persistence ONLY via an application-owned SPI port returning domain-shaped snapshots.** ArchUnit forbids `application..` depending on `adapters.persistence.entity..`/`repository..` (`APPLICATION_AND_DOMAIN_MUST_NOT_DEPEND_ON_PERSISTENCE_TYPES` `:189-198`) and forbids importing adapters at all (`LAYERED_BOUNDARIES` `:87-109`). So the port (`application.memory.spi.ProjectMemoryReadPort`) returns records; the `@Component ProjectMemoryPersistenceAdapter` in `adapters.persistence` does the SQL + mapping. [[application-cannot-import-adapters]] [Source: `architecture/ArchitectureRuleCatalog.java:56-80,87-109,189-198,351-360,602-621`.]
- **Closest projection precedent = `OperatorRunReadPort`.** Cross-table read-only aggregate over `workflow_runs` + `workflow_events` + typed `integration_links` via `NamedParameterJdbcTemplate` native SQL, returning `OperatorRunRowSnapshot`. Copy this port/adapter/snapshot shape (and the 4.1 perf result: 1000 runs ≤ 5s on V1 indexes, no new index). [Source: `application/workflow/spi/OperatorRunReadPort.java`, `adapters/persistence/OperatorRunPersistenceAdapter.java`; [[story-4-1-cli-operator-inspection]].]
- **The six substrates — LIVE vs BACKLOG (the crux):**

### Logging Requirements (project-wide standard)

Every story is expected to leave the touched services observable enough to debug a production incident without re-deploying. This is enforced via the "Logging instrumentation" task above.

- **Framework:** SLF4J + Logback. No `System.out`, no `printStackTrace()`.
- **Where to log (minimum surface for this story):**
  - `ProjectMemoryService.projectMemory` → `INFO` on entry (`projectId`) + `INFO` on success (`nodeCount`, `edgeCount`, `truncated`, `durationMs`); `WARN` when the ceiling truncates.
  - `ProjectMemoryPersistenceAdapter` → `DEBUG` per-query row counts (hot read path).
- **Required context keys:** `projectId` (+ node/edge counts). Use MDC (`MdcKeys.beginScope`) where practical, else structured parameters.
- **Forbidden in log output:** ticket titles, artifact bodies, `external_metadata`, secrets/tokens, PII. Labels are redacted for the RESPONSE but must NOT be echoed into logs — ids + counts only (`MdcKeys.sanitizeForLog`).
- **Test contract:** pin the completion-`INFO` line + the `WARN`-on-truncation line with a `ListAppender`/`OutputCaptureExtension`.
