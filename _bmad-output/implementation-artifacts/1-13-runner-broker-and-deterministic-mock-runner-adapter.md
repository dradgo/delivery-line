## Story

As a foundation developer,
I want `RunnerBroker` (runner lifecycle controller) + `RunnerExecutionService` + `ContextBundleService` + deterministic `MockRunnerAdapter` that exercises the full runner file contract including failure paths,
So that workflow, idempotency, and recovery tests can run deterministically without Docker, and the real Docker runners in Epic 3 plug into the same port without reshaping foundation contracts.

## Acceptance Criteria

1. **Given** the `application.runner` package, **Then** `RunnerBroker`, `RunnerExecutionService`, and `ContextBundleService` exist with a `RunnerAdapter` port (interface) that real + mock adapters implement.
2. **Given** `RunnerBroker.dispatch(workflowRunId, stage, idempotencyKey, actorContext)`, **When** called, **Then** it: (a) pre-reserves a public `rex_` runner-execution id via `PublicIdPrefixes.RUNNER_EXECUTION.next()`; (b) calls `IdempotencyService.checkAndReserve(idempotencyKey, "RunnerBroker.dispatch", actor.actorIdentity(), fingerprint)` with fingerprint = canonical hash of `(workflowRunId, stage, nextContextBundleVersion)` — on `REPLAY`, reconstructs and returns the prior `RunnerExecutionHandle` from the matching `runner_executions` row and exits without dispatching; (c) builds and validates the context bundle via `ContextBundleService.create(workflowRunId, stage, reservedRunnerExecutionId, contextBundleVersion)`; (d) within a single PostgreSQL transaction inserts the `runner_executions` row (public_id = reserved id, status `pending`, `timeout_at = now + executionConstraints.timeoutSeconds`, `last_activity_at = now`, `context_bundle_version` = derived monotonic) and appends a `RUNNER_STARTED` workflow event, then commits; (e) calls `IdempotencyService.complete(...)` with the row's public id as `resultRef`; (f) writes the redacted bundle bytes to `{deliveryline.home}/runner-scratch/{rex_id}/context-bundle.v1.json`; (g) delegates execution to the configured `RunnerAdapter.dispatch(...)`; (h) returns a `RunnerExecutionHandle` carrying the public `runnerExecutionId`.
3. **Given** `ContextBundleService.create(workflowRunId, stage, runnerExecutionId, contextBundleVersion)`, **When** called, **Then** it builds a `context-bundle.v1` document conforming to `deliveryline-runner-contracts/src/main/resources/schemas/context-bundle.v1.schema.json` (whose `required` fields include both `workflowRunId` and `runnerExecutionId`) assembled from: ticket summary, approved specification reference (if any), prior feedback references, artifact references, execution constraints (`timeoutSeconds`, `allowRawOutput`), and classification metadata — the content is redacted via `RedactionPolicyService` (story 1.10) before validation and must exclude credentials, `.env` files, shell history, and unrelated local paths. The bundle is validated with `RunnerContractValidator.validate(ValidationTarget.CONTEXT_BUNDLE, ...)` before it leaves the service; an invalid bundle raises a typed `DomainException(RUNNER_CONTRACT_VIOLATION)` and no runner-execution row is created.
4. **Given** `MockRunnerAdapter` in `adapters.runner`, **Then** it implements `RunnerAdapter` and accepts a scripted behavior config (per test) producing each of: happy-path success with a `spec` artifact, happy-path success with an `implementationPlan` artifact, happy-path success with a `prOutput` artifact, timeout (no result before deadline), crash (process exits non-zero with no result file), contract violation (result file present but invalid per `RunnerContractValidator`), non-zero exit (result file valid but `failureCategory` set), late result (delivered after timeout — produces `late_or_stale` artifact path via `ArtifactOperationService`), duplicate result (two results for same `runnerExecutionId` — second is rejected by `RunnerContractValidator.DUPLICATE_RUNNER_EXECUTION_ID` and surfaced as `runner_duplicate_result`), malformed output (truncated JSON — surfaces as `runner_malformed_output`).
5. **Given** each mock failure mode, **When** the broker processes the result, **Then** the corresponding `runner_executions.failure_category` and `workflow_events.failure_category` align with a registered `FailureCategory` value (`runner_timeout`, `runner_crash`, `runner_contract_violation`, `runner_non_zero_exit`, `runner_late_result`, `runner_duplicate_result`, `runner_malformed_output`). Workflow-run state transition rules are **split**:
   - **`runner_timeout`, `runner_crash`, `runner_contract_violation`, `runner_non_zero_exit`** → `WorkflowTransitionService.transition(EXECUTING → FAILED, ..., failureCategory)` (these are the 4 categories in `WorkflowTransitionTable.ALLOWED_RUNNER_FAILURE_CATEGORIES`).
   - **`runner_late_result`, `runner_duplicate_result`, `runner_malformed_output`** → the runner-execution row is marked `failed` and a `RUNNER_FAILED` workflow event is appended carrying the precise category, but **the workflow run's `current_state` is NOT changed** — the run remains `EXECUTING` (or whatever non-terminal state it was in). The originally-dispatched runner execution remains the active one for that workflow run; the workflow run does NOT auto-recover via a second dispatch. Operator-driven recovery (retry / takeover) is Epic 4's responsibility. A late artifact is routed through `ArtifactOperationService.recordOperation(...)` and ends up `late_or_stale` per story 1.12 AC10. This split is intentional: the workflow-state transition table stays minimal and operator-explicit; the runner-execution row is the precise diagnostic record.
   - State-mutation invariant: the workflow-run state mutation path is `WorkflowTransitionService.transition(...)` exclusively — no other path (verified by ArchUnit rule `ONLY_WORKFLOW_TRANSITION_SERVICE_MAY_MUTATE_WORKFLOW_STATE`).
6. **Given** runner result handling, **When** a result file arrives, **Then** the broker validates it with `RunnerContractValidator.validate(ValidationTarget.RUNNER_RESULT, ...)` (story 1.6) BEFORE calling `ArtifactOperationService.recordOperation(...)` — failed validation never produces approval-eligible artifacts and is logged with `failureCategory=runner_contract_violation`.
7. **Given** heartbeat / last-activity tracking, **Then** `runner_executions.last_activity_at` is updated on status polls or heartbeat file touches; stale detection threshold is configurable via `deliveryline.runner.stale-threshold-multiplier` (default `2.0`) and defaults to 2× the stage-declared `timeoutSeconds`. The DB CHECK constraint `ck_runner_executions_timeout_after_activity` (`timeout_at >= last_activity_at`) must continue to hold across every update — never reduce `timeout_at` below `last_activity_at`.
8. **Given** idempotent runner restart after broker crash, **When** the broker restarts and observes an in-flight `runner_executions` row (status `pending`/`running`), **Then** it either resumes monitoring (when the underlying process/file state is recoverable — e.g., result file present and validates) or marks the execution `orphaned` with `failureCategory=orphan` and emits a `recovery.reconciled` workflow event raising a reconciliation signal — never silently abandons the row. Resume vs orphan decision is deterministic and proven by tests.
9. **Given** the `runners.mock` Spring profile, **Then** the mock adapter is wired as the default `RunnerAdapter` bean; the real Docker runner adapter (Epic 3) activates only under explicit profile switch (`runners.docker`). Profile wiring is verified by a Spring context test that asserts `RunnerAdapter` resolves to `MockRunnerAdapter` under `runners.mock` and is not loaded under `runners.docker` in Epic 1.
10. **Given** the contract test suite, **Then** every mock failure mode produces the documented `DomainErrorCode` and `workflow_events.failure_category`, and a deterministic scenario library exists at two locations: (a) **production-classpath scenarios** under `deliveryline-backend/src/main/resources/runner-scenarios/` (one JSON scenario per AC4 failure mode plus the three happy-path artifact types — loaded by `MockRunnerAdapter` at runtime under any profile that activates `runners.mock`, including `local`, `test`, and `demo`); (b) **test-only adversarial scenarios** under `deliveryline-backend/src/test/resources/runner-scenarios/` for variants that should never reach production runtime (e.g., schema-version regressions, oversized payloads beyond `RunnerContractValidator` defaults). The two location convention is mandatory because `MockRunnerAdapter` is a main-source `@Profile("runners.mock")` bean — production-classpath fixtures are reachable, test-resource fixtures are not. Scenarios are referenced by name from `MockRunnerAdapter` and from `RunnerScenarioContractTest`.

**Scope guardrail:** Story 1.13 owns the runner lifecycle port, the deterministic mock adapter, and the context-bundle/result file contract enforcement at the application layer. It does **not** own the real Docker runner adapter (Epic 3), heartbeat-from-real-container details (Epic 3), full recovery-on-orphan workflows (Epic 4), or runner image build/orchestration (Epic 3/1.21 CI). Late/stale/orphan artifact rows are already owned by `ArtifactOperationService` / `ArtifactReconciliationService` (story 1.12) — this story only triggers those paths, it does not reimplement them.

### Anti-patterns to avoid (read this first)

- **Do NOT** call `WorkflowRunEntity.setCurrentState(...)` or `WorkflowRunStatePort.updateCurrentState(...)` from any class other than `WorkflowTransitionService` (ArchUnit `ONLY_WORKFLOW_TRANSITION_SERVICE_MAY_MUTATE_WORKFLOW_STATE` fails the build).
- **Do NOT** call `LocalArtifactStore.write(...)` from `RunnerBroker` or `MockRunnerAdapter` directly (ArchUnit `ARTIFACT_WRITES_MUST_GO_THROUGH_ARTIFACT_OPERATION_SERVICE` fails the build) — runner result artifacts enter the system only through `ArtifactOperationService.recordOperation(...)`.
- **Do NOT** add a Docker runner adapter, a runner Dockerfile, or runner image build/pull logic — Epic 3.
- **Do NOT** add operator-driven recovery flows (retry/rerun/resume/takeover/reconcile) — Epic 4 owns those; this story emits the `RECOVERY_RECONCILED` signal for orphans only.
- **Do NOT** introduce a third `Actor*` type — translate `ActorContext` → `WorkflowTransitionService.TransitionActor` at the boundary.
- **Do NOT** widen `WorkflowTransitionTable.ALLOWED_RUNNER_FAILURE_CATEGORIES` to include `runner_late_result` / `runner_duplicate_result` / `runner_malformed_output` — the AC5 split is intentional.
- **Do NOT** load runner scenarios from `src/test/resources/` at runtime in `MockRunnerAdapter` — `MockRunnerAdapter` is main-source and must read from `src/main/resources/runner-scenarios/`.
- **Do NOT** reduce `runner_executions.timeout_at` below `runner_executions.last_activity_at` — DB CHECK `ck_runner_executions_timeout_after_activity` will reject the write.
- **Do NOT** persist absolute host paths in any DB column or in the context bundle — store relative storage refs only, the same way `LocalArtifactStore` does.
- **Do NOT** log raw context-bundle bytes, raw runner-result bytes, payload contents, ticket body text, or anything that hasn't been through `RedactionPolicyService`.
- **Do NOT** use string literals for `RunnerExecutionStatus`, `FailureCategory`, `WorkflowEventType`, or `ArtifactType` values — always route through the registry enum (1.12 patches R11/M1/H6 killed every such literal; do not regress).
- **Do NOT** add a new Flyway migration unless a schema-level CHECK is genuinely required (V1 CHECKs already cover the runner-execution surface).

### Logging Requirements (project-wide standard)

Every story is expected to leave the touched services observable enough to debug a production incident without re-deploying. This is enforced via the "Logging instrumentation" task above.

- **Framework:** SLF4J + Logback (Spring Boot default). No `System.out`, no `printStackTrace()`.
- **Where to log (minimum surface):**
  - Public application-service methods → `INFO` on entry + `INFO` on success / `WARN` on typed-domain rejection / `ERROR` on unexpected failure.
  - Persistence-adapter writes → `INFO` with the public id being persisted; `WARN` on state-transition rejection; `ERROR` on `DataIntegrityViolationException` not mapped to a typed domain error.
  - Runner adapter dispatch / poll / result-read → `INFO` "dispatched runnerExecutionId=...", `WARN` on `runner_*` failure category, `ERROR` only on unhandled failure.
  - State-machine transitions → `INFO` "transitioned runnerExecutionId X from {from} to {to}" and the corresponding workflow `INFO` (which `WorkflowTransitionService` already emits).
  - Orphan-recovery scan → `INFO` per-batch summary; `WARN` per-item action taken (resume/orphan flip).
- **Required context keys** (MDC or structured parameters): `correlationId`, `workflowRunId`, `runnerExecutionId`, `idempotencyKey`, `actorIdentity`, `actorType`, `failureCategory` (when applicable).
- **Forbidden in log output:** context-bundle bytes, runner-result bytes, payload contents, raw secrets/tokens, raw PII, classification-restricted fields. Pass payloads through `RedactionPolicyService` before any string-ification.
- **Test contract:** new logging surfaces must be pinned by at least one focused test (`ListAppender`) so refactors can't silently delete them. See `ArtifactLoggingContractTest` for the pattern.

### Previous Story Intelligence (story 1.12 — Artifact Operations Skeleton, done 2026-05-11)

The dev agent should review `_bmad-output/implementation-artifacts/1-12-artifact-operations-skeleton.md` for the full review log. The patterns 1.12 settled on that **apply directly here**:

- **Outbox-style transaction boundary.** DB row + workflow event commit in one transaction; external I/O (file write, runner dispatch) happens **after** commit. 1.12 enforced this for `recordOperation`; 1.13 enforces the same shape for `RunnerBroker.dispatch`.
- **Application services depend on application-owned SPI ports**, never on JPA entities or repositories directly (rule `APPLICATION_AND_DOMAIN_MUST_NOT_DEPEND_ON_PERSISTENCE_TYPES` in `ArchitectureRuleCatalog.java:125`).

- **Per-item `REQUIRES_NEW` transactions** for batch scans (1.12 patch M2 in `ArtifactReconciliationService`). Apply the same shape to `RunnerBroker.recoverOnStartup()`.
- **Registry-backed enums everywhere.** No string literals for status / failure category / event type. 1.12 patches R11/M1/H6 killed every raw `"timed_out"` / `"create"` / `"system"` literal — do not regress.
- **`ActorContext` is mandatory** for application-facing service methods that emit workflow events. No `"system"`/`ActorType.SYSTEM` literal fallbacks at the service layer. Use `ActorContext.SYSTEM` only when the legitimate caller is the system itself (e.g., the orphan-recovery scan).

- **Concurrency conflict mapping.** `OptimisticLockingFailureException` → `CONCURRENT_TRANSITION_CONFLICT` (already in `WorkflowTransitionService`); `DataIntegrityViolationException` on unique constraints → typed retryable conflict (mirror 1.12 patches H9/M5/R6).

### Collateral infrastructure repair (uncovered by full backend regression)

The targeted runner-test suite from Session 2 was green, but running `./mvnw -pl deliveryline-backend test` (full backend) surfaced four pre-existing context-load failures that had been masked behind narrower test selectors. Fixed alongside the 6 review patches so the regression closes cleanly:

- `RunnerExecutionPersistenceAdapter`, `RunnerBroker`, `RunnerExecutionService`, `MockRunnerAdapter` had two constructors each (production + package-private test-clock variant); Spring Boot 4 refused to auto-pick. Annotated each production constructor with `@Autowired`.
- `TicketSummaryProvider` (port) had no implementation, so any context including `ContextBundleService` failed to start. Shipped `adapters/runner/StubTicketSummaryProvider` as the Epic-1 placeholder the story Dev Notes called for (1.14 replaces it with the real Linear-fetching adapter).
- `RunnerContractValidator` is a plain class in `deliveryline-runner-contracts` with no Spring annotations; the autowire path expected a bean. - `MockRunnerAdapter` and `MockRunnerScenarioRegistry` were `@Profile("runners.mock")` only, so context-load tests without that profile had no `RunnerAdapter` bean. Switched to `@Profile("!runners.docker")` — mock is the default per AC9, docker stays opt-in.
- `deliveryline-backend/src/test/resources/application.yml` did not include the `deliveryline.runner.*` namespace, so `RunnerProperties` constructor binding got `0.0` for `staleThresholdMultiplier` and rejected. Added the runner namespace block to the test profile (`scheduling.enabled=false` to keep the `@Scheduled` ticks out of unit/contract runs).
