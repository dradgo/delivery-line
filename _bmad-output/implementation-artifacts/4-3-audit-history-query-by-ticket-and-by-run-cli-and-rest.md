# Story 4.3: Audit History Query by Ticket and by Run — CLI + REST

Status: done

## Story

As a Workflow Owner investigating an audit question ("show me everything that happened to LIN-123 across all its workflow runs"),
I want `deliveryline audit query --ticket LIN-123` (CLI) + `GET /api/v1/audit/by-ticket/{ticketRef}` + `GET /api/v1/audit/by-run/{workflowRunId}` (REST) returning a flat, filterable, cursor-paginated event stream,
so that FR29 (workflow owners can query audit history by ticket and by run) is wired with a CLI + REST surface — supporting compliance reviews, post-incident investigations, and pattern analysis.

## Context & Central Reconciliation (READ FIRST)

**This is the THIRD story of Epic 4 (Failure Handling, Recovery & Reconciliation). It is a pure READ-ONLY audit-query layer over the existing append-only `workflow_events` table.** You build a NEW application read service (`AuditQueryService` in a new `application.audit` package), a NEW read seam (SPI port + persistence query), a NEW CLI command group (`deliveryline audit query`), and a NEW REST controller (`/api/v1/audit/...` with two GET endpoints). **You do NOT touch any write path, any transition, the `RecoveryService`, the queue, any runner logic, or the event-emission side.** No new `WorkflowState`/`WorkflowEventType`/`AllowedAction`. One new `DomainErrorCode` (`INVALID_AUDIT_FILTER`) and one Flyway index migration.

Two existing surfaces are the closest analogues — **read both before coding:**
- **Story 4.1** (`4-1-cli-operator-inspection-deliveryline-operator-status.md`) — the sibling E4 read-only CLI story. It sets the house discipline you MUST mirror: typed view/result records nested in the application service (NOT in `...spi`, so the CLI adapter can import them), a new SPI read seam with a native/JPQL query, a `@CommandGroup` CLI adapter that only parses + delegates + renders, ANSI gated on TTY, a `schemas/cli/*.v1.schema.json` JSON contract + contract test, and an ArchUnit boundary rule. This story adds the REST + Flyway dimensions 4.1 didn't have.
- **The existing `workflow history` command + `GET /workflows/{id}/events` endpoint** — both are RUN-SCOPED event readers over the same `workflow_events` table. `WorkflowInspectionService.listHistory` (`:1440-1482`) → `WorkflowEventView`, and `WorkflowController.getWorkflowEvents` (`:521-557`). Your `by-run` query does what `listHistory` does but with the richer filter set + cursor pagination + a flat `AuditEventRow` shape; your `by-ticket` query has NO precedent (no existing query joins events across all runs of a ticket). REUSE the redaction + details-filter helpers these surfaces already use — do NOT reinvent them.

### HEADLINE RECONCILIATIONS (epic AC text drifts from live code — these bindings win)

1. **`correlationId` is NOT a column on `workflow_events` — it lives in `details->>'correlationId'` (JSONB).** AC1 types `correlationId` as a first-class row field and AC9 asks for `idx_workflow_events_correlation_id` "for correlation-based lookup". **There is no such column.** Correlation is stored inside the `details` JSONB under key `correlationId` (precedent: `WorkflowEventRepository.findLatestCorrelationIdInDetails`, a native query pulling `we.details->>'correlationId'`). Bind: the `AuditEventRow.correlationId` field is read from `details->>'correlationId'` (nullable — some events have none). **DROP the `idx_workflow_events_correlation_id` index entirely** — no filter in this story queries by correlation (AC2 filters are `event-type` / `actor` / `since` / `until` / `limit` / `cursor`), the existing `idx_workflow_events_details_gin` already covers JSONB containment, and an index on a non-existent column is a compile-time error. [Source: V1__create_workflow_core_tables.sql:39-56 (no correlation_id); WorkflowEventRepository.java:104-118 (details->>'correlationId')]

2. **`linkedArtifactId` is NOT a column on `workflow_events` — the FK is the reverse direction (`artifacts.linked_event_id`).** AC1's `linkedArtifactId?` per row cannot be selected from the events table. Bind: read it best-effort from `details->>'artifactId'` when present (nullable), NOT via a reverse `artifacts` join (that would multiply rows and cost a JOIN for a rarely-populated field). Document that it is best-effort/details-sourced. [Source: V1:115,124-125,142,156 artifacts.linked_event_id; WorkflowEventEntity.java (no artifact column)]

3. **The epic's "Flyway V7" is WRONG — V7 is long-taken (`V7__add_spec_rejection_loop_columns.sql`).** Highest on-disk is **V33**; sibling in-flight story **3h-2 claims V34**; no story claims V35. Author the migration as **`V35__add_audit_query_indexes.sql`** — but **re-confirm the head at implementation time** and take the next FREE number (the cross-branch Flyway collision trap is real — [[flyway-v31-cross-branch-collision]], [[flyway-v31-cross-branch-collision]]). [Source: db/migration highest = V33; 3h-2 story claims V34; 4-1 story Reconciliation 8]

4. **`CREATE INDEX CONCURRENTLY` cannot run inside Flyway — DROP the `CONCURRENTLY` from AC9.** Every Flyway migration runs inside a transaction, and Postgres forbids `CONCURRENTLY` in a transaction. The repo has NO non-transactional-migration precedent and has deliberately avoided one (see the explicit comments in `V6`, `V21`, `V30`, `V32` all using plain `CREATE INDEX`). Use plain `CREATE INDEX IF NOT EXISTS`; the tables are small in MVP so lock contention is a non-issue. Document the deviation from AC9. [Source: V6:18-20; V21:15-16; V30:20-21; V32:15-16]

5. **The index set is RE-SCOPED. Of the two AC9 indexes, keep ONE and add ONE the epic missed.** Your migration (`V35`) creates:
   - **KEEP** `idx_workflow_events_event_type_created_at` on `workflow_events (event_type, created_at)` — `event_type` has NO index today and the `--event-type` filter (AC2) needs it. (Consider `(event_type, created_at DESC, id DESC)` to also serve the keyset order.)
   - **DROP** `idx_workflow_events_correlation_id` — Reconciliation 1.
   - **ADD (epic missed this)** `idx_integration_links_external_ref_type` on `integration_links (external_ref, integration_type)` — the by-ticket query filters `WHERE external_ref = ? AND integration_type = 'linear'`, but the ONLY existing index `idx_integration_links_run_id_type_created_at` is **run-id-first**, so an `external_ref`-first lookup is NOT index-covered. Without this index the by-ticket AC8 5s/200-event target is at risk on a large `integration_links` table.
   - The `by-run` event query rides the existing `idx_workflow_events_workflow_run_id_created_at` (V1) — no new index needed for it. [Source: V1:319-320,336; agent DB map]

6. **`integration_type` value is `'linear'`, NOT `'linear_ticket'`.** AC3 says "via `integration_links` of type `linear_ticket`" — the stored value is the literal `'linear'` (constant `IntegrationLinkService.LINEAR_INTEGRATION_TYPE = "linear"`; DB CHECK permits only `'linear'|'github_pr'|'internal_subtask'`). `linear_ticket` appears ONLY in prose/Javadoc, never as a persisted value. Bind: filter `integration_type = 'linear'`. [Source: IntegrationLinkService.java:74; V1:251; V30]

7. **There is NO existing query that returns all runs for a ticket, and cross-run uniqueness is deliberately NOT enforced — a retried ticket legitimately has MANY `integration_links` rows.** Every existing finder (`findActiveLinearTicketLink`, `findActiveByTypeAndExternalRef`, …) returns a SINGLE active link (`archived_at IS NULL AND sync_status <> 'superseded'`). For AC3 ("show me all governed runs for this ticket including any retried runs") you must add a NEW query that collects **DISTINCT `workflow_run_id`** for `external_ref = ? AND integration_type = 'linear'` **WITHOUT the active-only filter** (you WANT superseded/archived links too — those point at the earlier runs). Do NOT reuse the active-only finders. [Source: V1:256 "cross-run uniqueness deferred"; IntegrationLinkRepository.java active-only finders]

8. **Cursor pagination is NET-NEW to this codebase — no idiom to mirror, and `created_at` alone is an UNSTABLE sort key.** Everything else pins `PageRequest.of(0, limit)` (offset page 0). AC1/AC6/AC8/AC11 require a `nextCursor`. Two traps: (a) `workflow_events.created_at` collides within a JVM clock tick and its index is **non-unique**, so ordering by `created_at` alone is non-deterministic between same-tick appends ([[post-commit-hook-needs-requires-new]] — see deferred-work "OffsetDateTime.now() event-ordering collisions"); (b) offset paging drifts under concurrent inserts. Bind: **keyset/seek pagination on the composite `(created_at DESC, id DESC)`** — `id` (bigserial PK) is the monotonic tiebreaker. Precedent for the ordering exists: `findLatestByWorkflowRunPublicId` already orders `createdAt desc, id desc`. The `nextCursor` is an OPAQUE base64 token encoding `(created_at, id)` of the last returned row; the next page's predicate is `(created_at, id) < (cursor.createdAt, cursor.id)`. A malformed/undecodable cursor → `INVALID_AUDIT_FILTER`. [Source: WorkflowEventRepository.java:24-32; deferred-work.md:502]

9. **New `DomainErrorCode.INVALID_AUDIT_FILTER` triggers the three-sites + gate-test fan-out — but reuse `INVALID_TIME_RANGE` for `since>until`.** AC2 names `INVALID_AUDIT_FILTER` for bad filter values. Adding a `DomainErrorCode` requires all THREE sites or foundation-gate reds ([[new-domainerrorcode-three-sites]]): (1) the enum `DomainErrorCode.java`, (2) `ProblemDetailsCatalog.register(...)` (map to **400**, retryable=false), (3) the manifest `src/test/resources/contracts/openapi/registry-api-schema-placeholders.json` `problemTypeUris` (unique `https://deliveryline.local/problems/invalid-audit-filter` URI); plus keep `DomainRegistry.domainErrorCodes()` aligned. Gate tests that will red otherwise: `ProblemDetailsCoverageFoundationContract`, `RegistryContractTest.domainErrorCodesStayAlignedWithProblemTypeOwnershipManifest`. **Reuse the EXISTING `INVALID_TIME_RANGE` (`DomainErrorCode:42`) for `since > until`** — don't invent a second time-range code. Use `INVALID_AUDIT_FILTER` for: unknown `event-type` token, malformed `cursor`, out-of-range `limit`, mutually-exclusive `--ticket`/`--run` at the SERVICE seam. (The CLI XOR-guard may throw the existing `INVALID_COMMAND_PAYLOAD` per the `parseBatchTickets` precedent — see Reconciliation 11.) [Source: DomainErrorCode.java:42,59; ProblemDetailsCatalog.java; registry-api-schema-placeholders.json:113]

10. **Event content redaction: `reason` is NOT redacted today — only the `details` map is. You must extend redaction to `reason`.** AC7 requires event content (both `reason` and `details`) to pass through `RedactionPolicyService`. The existing read surfaces (`listHistory`, `getEventStream`) route ONLY `details` through `redactDetails` (`WorkflowInspectionService:2466-2490`, hard-coded claim `DataClassification.SHAREABLE_REDACTED`) and pass `reason` RAW. Bind: for `AuditEventRow`, redact `reason` via `redactionPolicyService.redact(reason, DataClassification.SHAREABLE_REDACTED.value()).sanitizedText()` AND redact `details` via the same `redactDetails`/`sanitizeWireDetails` pattern (strip `WorkflowEventDetailKeys.SERVER_ONLY_KEYS` first). **There is NO per-event classification column and NO generic `[CONTENT REDACTED]` placeholder** — so AC7's "`local-only` events → `[CONTENT REDACTED — see correlationId in local logs]` opacity" clause is UNREACHABLE for standard events (no event carries a `local-only` classification). Treat every event as claim=`SHAREABLE_REDACTED` scrubbed on the fly; document the local-only opacity clause as a no-op with no event source today. Also add the missing control-char guard on `reason` for log/CLI safety ([[reject-reason-1024-size-cap]] neighbor; deferred-work "no newline/control-char guard on setReason"). [Source: WorkflowInspectionService.java:2466-2490,2441-2450; DataClassification.java:6-9; RedactionCategory.java]

11. **`--ticket` / `--run` mutual exclusion has an in-repo precedent — mirror it exactly.** No Spring Shell framework construct; the XOR is validated in the method body. Mirror `parseBatchTickets` (`WorkflowCommands.java:400-410`): `boolean hasTicket = ...; boolean hasRun = ...; if (hasTicket == hasRun) throw new DomainException(INVALID_COMMAND_PAYLOAD, "Provide exactly one of --ticket or --run", details)`. (Neither-or-both both reject.) [Source: WorkflowCommands.java:314,400-410]

12. **`--since` / `--until` are ISO-8601 absolute `OffsetDateTime`, matching the sibling `history --since`.** The existing per-run event reader `workflow history --since` takes an ISO-8601 absolute timestamp (`parseSince`), NOT a relative `1h`/`7d` token (that relative form is 4.1's operator-status convention). Since 4.3 is the direct multi-surface analogue of `history` over the SAME table, bind `--since`/`--until` to ISO-8601 absolute `OffsetDateTime` (reuse the `parseSince` helper). REST `?since=`/`?until=` accept the same ISO instant. `since > until` → `INVALID_TIME_RANGE`. [Source: WorkflowCommands.java:1799-1846 history; DomainErrorCode.INVALID_TIME_RANGE]

13. **Result/row records live in `application.audit` (NOT `...audit.spi`), so BOTH the CLI adapter and the REST controller can import them.** The ArchUnit CLI/REST boundary forbids `adapters.cli`/`adapters.rest` from depending on `...spi` or persistence. `AuditQueryResult` / `AuditEventRow` / `AuditQueryFilter` are public records in `application.audit` (nested in `AuditQueryService` or siblings). The SPI-layer snapshots (`AuditEventRowSnapshot`, `AuditEventPageSnapshot`) stay in `application.audit.spi` and are NEVER imported by adapters. Mirror 4.1 Reconciliation 2. [Source: 4-1 Reconciliation 2; ArchitectureRuleCatalog REST/CLI boundary]

## Dev Notes

### Relevant architecture patterns and constraints

- **The read seam.** No JPA/`EntityManager`/native query in `AuditQueryService` — it composes the `AuditEventReadPort` (interface in `...audit.spi`, impl in `adapters.persistence`) returning intentionally-lossy snapshots, then applies redaction + cursor encoding. Mirror `WorkflowInspectionService.listHistory` (`:1440-1482`) for the run-scoped event read + `listRuns` (`:1506`) for the clamp-limit convention (`MAX_LIST_PAGE_SIZE=200`, `Math.min(Math.max(limit,1),200)`). Every method `@Transactional(readOnly=true)`.
- **Why a new `application.audit` package (not `WorkflowInspectionService`).** `AuditQueryService` is the epic's named surface (AC1) and the by-ticket cross-run join is a distinct concern from single-run inspection. Result records go in `application.audit` (importable by both the CLI adapter and REST controller — the ArchUnit CLI/REST boundary forbids importing `...spi`/persistence). SPI snapshots go in `application.audit.spi`. This mirrors 4.1's placement discipline (Reconciliation 13).
- **Event data model (Reconciliation 1/2).** `workflow_events` columns: `public_id`(`evt_`), `workflow_run_id`(FK→`workflow_runs.id`), `event_type`, `prior_state`, `resulting_state`, `actor_identity`, `actor_type`, `reviewer_role`, `reason`, `failure_category`, `intervention_marker`, `details`(jsonb), `stage_duration_ms`, `rejection_taxonomy`, `created_at`, `archived_at`. **No `correlation_id` column** (it's `details->>'correlationId'`), **no `linked_artifact_id` column** (reverse: `artifacts.linked_event_id`; best-effort `details->>'artifactId'`). `actor_type` is a `String` in the entity exposed as `ActorType` (`human|agent|system|service_account`). `event_type`↔`WorkflowEventType` and `prior_state`/`resulting_state`↔`WorkflowState` via `PersistedRegistryValues`. `created_at` is `OffsetDateTime`.
- **Cursor / stable ordering (Reconciliation 8).** Order `created_at DESC, id DESC` — `id` (bigserial) is the monotonic tiebreaker because `created_at` collides within a JVM tick and `idx_workflow_events_workflow_run_id_created_at` is NON-unique (deferred-work.md:502). Keyset predicate for page N+1: `(created_at, id) < (cursor.createdAt, cursor.id)`. Fetch `limit+1` to know if a next page exists; `nextCursor` encodes the last KEPT row's `(created_at, id)`. This is net-new — there is no in-repo cursor idiom (everything else is `PageRequest.of(0, limit)`). Keep the token OPAQUE (base64) so its internal shape isn't a wire contract.
- **Redaction (Reconciliation 10).** Reuse `RedactionPolicyService` (`application.security`) with claim `DataClassification.SHAREABLE_REDACTED.value()`. Existing `WorkflowInspectionService.redactDetails` (`:2466-2490`) + `sanitizeWireDetails` (`:2441-2450`, strips `WorkflowEventDetailKeys.SERVER_ONLY_KEYS`) handle the `details` map — copy that pattern. **`reason` redaction is NEW** — the current surfaces pass `reason` raw; add `redact(String, claim).sanitizedText()` + a CR/LF/TAB control-char guard. No event has a `local-only` classification (no classification column on events), so the `[CONTENT REDACTED]` opacity clause is a documented no-op.
- **Integration links (Reconciliation 6/7).** `integration_type = 'linear'` (constant, not `'linear_ticket'`). Cross-run uniqueness is NOT enforced (`V1:256`), so a retried ticket has multiple rows — collect DISTINCT `workflow_run_id` for `external_ref=? AND integration_type='linear'` WITHOUT the active-only filter (you want superseded links to earlier runs). No existing finder does this — add one. The existing `idx_integration_links_run_id_type_created_at` is run-first and does NOT cover external_ref lookup → new `idx_integration_links_external_ref_type`.
- **CLI (Spring Shell 4.0.2).** Imports from `org.springframework.shell.core.command.annotation`. New `@CommandGroup(name="audit", prefix="deliveryline")` → registered `deliveryline audit query`. Mirror `WorkerCommands` (dual-ctor `@Autowired`, returns `String`). ANSI via `WorkflowCommandOutputs.ESC` constants gated on `!json && interactivity.isInteractive()`; JSON via `writeJson`. Renderers live on `WorkflowCommandOutputs` (NOT a `*Commands` class — ArchUnit forces `@CommandGroup` on those). XOR-guard mirrors `parseBatchTickets` (`WorkflowCommands.java:400-410`).
- **REST (read GET conventions).** Mirror `WorkflowController.listWorkflows` (`:145-185`) / `listStepExecutions` (`:676-717`): `@GetMapping`, `@RequestParam(required=false)` with defaults, direct DTO return (no envelope), static `from` mapper. ### Logging Requirements (project-wide standard)

Every story is expected to leave the touched services observable enough to debug a production incident without re-deploying. This is enforced via the "Logging instrumentation" task above.

- **Framework:** SLF4J + Logback. No `System.out`, no `printStackTrace()`. (CLI stdout is the command's returned `String`, not a logger.)
- **Where to log (minimum surface for this story):**
  - `queryByRun`/`queryByTicket` → `INFO` on entry with resolved filter + `INFO` on success with `totalCount`/`returnedRows`/`durationMs`; `DEBUG` for the port-query calls.
  - Filter rejections → `WARN` at the `INVALID_AUDIT_FILTER`/`INVALID_TIME_RANGE` raise site with the offending value (sanitized).
  - CLI `audit query` → the structured completion log line (AC10) at `INFO` (success) / `WARN` (typed failure) — mirror `WorkflowCommands.history`. REST → an INFO line with `operationId` + filter summary + `resultCount`.
- **Required context keys** (MDC or params): `correlationId` + the filter summary; per-row ids only at `DEBUG`.
- **Forbidden in log output:** payload bytes, secrets/tokens, raw PII, and the RAW (un-redacted) `reason`. Sanitize user-supplied `--ticket`/`--actor`/`--event-type` before logging.
- **Test contract:** pin the completion-log line + the `WARN`-on-invalid-filter line with `OutputCaptureExtension`.

### Completion Notes List

- **All 7 tasks + logging complete; full verify green** on real-PG Docker (unit 1163, foundation-gate, ITs, ArchUnit 60, OpenAPI contract). Read-only audit-query surface shipped; no write path touched.
- **Persistence is native SQL via `NamedParameterJdbcTemplate`** (mirrors `OperatorRunPersistenceAdapter`), NOT JPA — keyset `(created_at, id) < (cursorTs, cursorId)` on `ORDER BY created_at DESC, id DESC`, fetch `limit+1` for `nextCursor`, separate `COUNT(*)` for the full-set `totalCount`. by-ticket scopes via `we.workflow_run_id IN (SELECT DISTINCT il.workflow_run_id FROM integration_links WHERE external_ref=? AND integration_type='linear')` with NO active-only filter (superseded links to retried runs included — Reconciliation 6/7). `event_type IN (:eventTypes)` uses a placeholder-list trick when the filter is inactive (same as operator adapter).
- **TRAP fixed — no Spring `ObjectMapper` bean:** this app does not expose an `ObjectMapper` bean (that's why `WorkflowCommandOutputs` injects `ObjectProvider<ObjectMapper>` with a fallback). Injecting `ObjectMapper` into `AuditEventPersistenceAdapter` failed full-context load (`NoSuchBeanDefinitionException`). Fixed by owning a private `new ObjectMapper()` for `details` JSONB→map parsing (no custom modules needed).
- **CLI registration corrects the story's literal spec:** Spring Shell 4.0.2 registers `groupPrefix + " " + @Command.name` (group `name` is help-only — confirmed by `OperatorCliCommandRegistrationIT`). Task 4's naive `prefix="deliveryline"` + `name="query"` would register `deliveryline query`; used **`prefix="deliveryline audit"` + `name="query"`** to get `deliveryline audit query`. Pinned by `AuditCliCommandRegistrationIT`.
- **Redaction (NET-NEW `reason` — Reconciliation 10):** `reason` → `RedactionPolicyService.redact(String, shareable-redacted).sanitizedText()` + control-char strip (`\p{Cntrl}`→space); `details` → strip `SERVER_ONLY_KEYS` + `redact(Map, ...)` then extract `correlationId`/`artifactId` from the **redacted** JSON (they are `details` keys, not columns — Reconciliation 1/2). Verified in `AuditQueryServiceIT` with a `ghp_…` token reason (redacted) + a newline (stripped) + `idempotencyKey` in details (stripped, `correlationId`/`artifactId` surface).
- **404 vs empty:** by-run adds a `runExists` seam → `RUN_NOT_FOUND` (404) for a well-formed-but-absent `run_` id; by-ticket unknown ticket → valid empty result (Reconciliation 3/AC3).
- **Flyway V35** (V34 already on disk from 3h-2) — `idx_workflow_events_event_type_created_at (event_type, created_at DESC, id DESC)` + `idx_integration_links_external_ref_type (external_ref, integration_type)`; plain `CREATE INDEX IF NOT EXISTS`, NO `CONCURRENTLY`, NO correlation-id index (Reconciliation 1/4/5).
- **New ArchUnit rules (2):** `AUDIT_QUERY_RESULT_VIEWS_REFERENCED_ONLY_BY_SERVICE_CLI_REST` (result records confined to service+CLI+renderer+controller+DTO) and `AUDIT_SPI_SNAPSHOTS_NOT_IMPORTED_BY_ADAPTERS` (audit.spi snapshots out of CLI/REST). `AuditQueryFilter` intentionally unrestricted (adapters build it).
- **Deferred / documented:** AC7 `[CONTENT REDACTED — local-only]` opacity is a no-op — no event carries a `local-only` classification (no classification column). `linkedArtifactId` is best-effort `details->>'artifactId'` (OQ-1). No FE UI (client regen only, to keep the drift gate green). REST controller test is `@WebMvcTest` (mock service, mirrors `OperatorControllerTest`); `X-Correlation-Id` echo is `CorrelationIdFilter` infra, not asserted at the slice.
