# Story 4.15: Artifact Reconciliation — DB/File Drift Detection

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a backend developer + workflow owner needing visibility into DB/file drift,
I want a scheduled `ArtifactDriftDetectionJob` that scans for orphan operations (stale-pending DB rows), missing payloads (file deleted after `markAvailable`), and checksum mismatches, plus a read surface so operators can list current drift,
so that NFR2 (workflow run must preserve produced artifacts after interruption) is enforced operationally and drift is visible **before** reviewers encounter it during approval.

## Context & Central Reconciliation (READ FIRST)

**This is the DETECTION half of the Epic-4 artifact-reconciliation split (detection = 4.15, operator-driven repair = 4.16, lineage/fork governance = 4.16a).** You build: (1) a NEW scheduled sweep that scans three drift categories, (2) a NEW `artifact_drift_detected` table + a `V36` migration, (3) a NEW read surface `listUnresolvedDrift(...)`, (4) two new registry values + one persisted `DriftCategory`, and (5) Prometheus metrics. **You detect and record only — you NEVER mutate an artifact/operation's status, NEVER set `resolved_*`, and NEVER touch `RecoveryService`.** Every repair action (`markOperationFailed/Complete`, `markCorrupted`, `restoreFromBackup`, `reVerifyChecksum`), the `resolved_at`/`resolved_by_action_id` writes, and the `ArtifactStatus.corrupted` value are **story 4.16** — out of scope here.

This story extends the **already-complete** `ArtifactReconciliationService` (`org.dradgo.application.artifact`) — the epic calls it a "skeleton from story 1.12" but it is a full 297-line service that already detects **and auto-repairs** stale-pending orphan operations (`reconcileStalePendingOperations()`). Read it end-to-end (`ArtifactReconciliationService.java`) before starting — it is the event-emission and per-item-isolation precedent you mirror, and the source of the orphan-detection query you reuse.

The scheduling + sweep shape has **no existing artifact precedent** — mirror the **story 3f-8 split-rollup sweep** (`SplitRollupSweepConfiguration` + `SplitRollupReconciliationSweepService`) instead. There is currently **no `@Scheduled` bean that drives any artifact reconciliation** — `reconcileStalePendingOperations()` is called only from tests today.

### HEADLINE RECONCILIATIONS (epic AC text drifts from live code / omits critical mechanics — these bindings win)

1. **DETECTION-ONLY. No state mutation, no resolve, no repair, no new `ArtifactStatus`.** All three categories do exactly two things per detected drift: (a) INSERT one `artifact_drift_detected` row with `resolved_at = NULL` + `resolved_by_action_id = NULL`, (b) append one `artifact.driftDetected` workflow event. The job **never** flips `artifacts.status` / `artifact_operations.status`, **never** writes `resolved_*`, and **does NOT add `ArtifactStatus.corrupted`** (that value + the `markCorrupted` repair are story 4.16 AC2). The existing `reconcileStalePendingOperations()` auto-flip method is **NOT invoked by this new job** (see Reconciliation 4 + OQ-1). [Source: epic-04-recovery.md Story 4.15 (all ACs record/emit only); Story 4.16 AC1–AC2 owns all mutation]

3. **No `@Scheduled` artifact scheduler exists — mirror the 3f-8 split-rollup sweep exactly.** The epic implies an existing scheduler ("formalizes the scan into a job") but there is none. [Source: infrastructure/config/SplitRollupSweepConfiguration.java; application/workflow/SplitRollupReconciliationSweepService.java; test application.yml disabled-sweep convention]

4. **Idempotent detection is MANDATORY — without a "one active drift per (target, category)" partial-unique guard, every 15-min tick re-inserts rows and re-fires `artifact.driftDetected` events.** The epic omits this entirely. Add a partial unique index `uq_artifact_drift_detected_active` on `(drift_category, artifact_id, artifact_operation_id) WHERE resolved_at IS NULL`, and make the insert **insert-if-absent** (catch the unique-violation and skip, or `ON CONFLICT DO NOTHING`) so a persisting drift produces **exactly one** unresolved row + **one** event across repeated scans ([[one-active-per-key-needs-partial-unique-index]], [[caught-idempotency-conflict-poisons-shared-tx]] — prevent the flush inside the per-item `REQUIRES_NEW` tx, don't just catch). A drift that 4.16 later resolves and that then recurs is allowed to produce a NEW row (the partial index only guards the *unresolved* slice). [Source: no dedup in epic AC1/AC2; one-active-per-key precedent V4 uq_artifact_operations_pending_per_artifact]

5. **Scanning `available` artifacts needs a NEW read seam + a NEW index — `ArtifactRecordPort` cannot list them today.** Every finder on `ArtifactRecordPort` is scoped to a single `(workflowRunId, artifactType)` or a single id; there is **no global "list all available" method** and **no index on `artifacts.status`**. Add: (a) a paged/bounded port method (e.g. `List<ArtifactRecordSnapshot> findAvailableCreatedBefore(Duration minAge, int batchLimit)`), (b) its `adapters.persistence` native query, (c) a partial index `idx_artifacts_status_created_at ON artifacts(status, created_at) WHERE status='available'` in V36. Missing-payload check = `!payloadStore.isReadable(snapshot.storageRef())`; checksum check = `ArtifactChecksum.digestHex(snapshot.checksumAlgorithm(), payloadStore.readBytes(ref).orElseThrow()).equals(snapshot.checksumValue())`. [Source: application/artifact/spi/ArtifactRecordPort.java; V1 artifacts indexes (none on status); ArtifactChecksum.digestHex; LocalArtifactStore.isReadable/readBytes]

- **The reconciliation precedent (reuse heavily).** `ArtifactReconciliationService` (`org.dradgo.application.artifact`, `@Service`, 297 lines) is your model: a `PROPAGATION_REQUIRES_NEW` per-item `TransactionTemplate` (P23 per-item exception isolation — one bad artifact must not abort the batch), a per-tick fresh `UUID` correlationId (P18 — never reuse `ActorContext.SYSTEM.correlationId`), DB-side staleness (`findPendingOlderThan` runs `created_at < now()-threshold` in SQL, not JVM subtraction — P-clock-skew), and `ArtifactEventPort.append(new ArtifactEventRecord(...))` with `ActorContext.SYSTEM` + `OffsetDateTime.now(clock)` + a `Map.of(...)` details payload. Your `ArtifactDriftDetectionService` copies all of this; it does NOT copy the *mutation* (markFailed/markFailedOrphan) — detection-only (Reconciliation 1).
- **The sweep/scheduling precedent (3f-8).** `SplitRollupSweepConfiguration` (`infrastructure.config`) = `@Configuration @EnableScheduling @ConditionalOnProperty @Scheduled(fixedDelayString=...)` calling `SplitRollupReconciliationSweepService.sweep()` which returns a bounded `SweepResult(found, recovered, batchLimitHit)` and WARNs on a full batch.
